# 用户点控产品需求文档

| 项目 | 内容 |
| --- | --- |
| 文档版本 | V1.0 |
| 文档状态 | 已确认 |
| 更新日期 | 2026-07-25 |
| 适用对象 | 客户、产品、设计、开发、测试、运营管理人员 |
| 功能名称 | 用户点控 |

## 1. 产品背景

平台现有交割、永续、现货等交易模块。各模块可根据自身业务规则计算用户的交易盈亏，但缺少一个针对单个用户进行集中管理的入口。

本功能在“用户管理”中增加用户级点控能力，同时在交割、永续、现货三个交易模块下提供当前模块的用户点控入口。管理员设置控盘类型和控盘方式，点控规则默认长期生效；具体金额、成交价格及结算结果仍由各业务模块按照自身规则计算。

## 2. 产品目标

1. 支持管理员针对单个用户用户点控设置交易三模块的控盘类型和控盘方式。
2. 支持管理员在业务模块中单独设置该模块的用户点控规则。
3. 新建或修改点控时默认长期生效，不在点控弹窗中提供控制周期选择。
4. 保证用户点控设置的完整性：任一交易模块设置失败时，交易三模块均不发生变化。
5. 保留设置、修改、覆盖、取消、执行及失败记录，方便查询和审计。
6. 用尽量少的状态表达完整业务过程，避免增加操作和理解成本。

## 3. 功能范围

### 3.1 本期包含

| 模块 | 点控能力 |
| --- | --- |
| 交割 | 盈利、做高盈利、做低盈利、亏损、做高亏损、做低亏损 |
| 永续 | 盈利、做高盈利、做低盈利、亏损、做高亏损、做低亏损 |
| 现货 | 盈利、亏损；做高/做低方式不参与现货计算，现货按默认方式处理 |

### 3.2 本期不包含

- 不在点控设置中填写具体盈利金额、亏损金额或成交价格。
- 不通过用户点控修改公共行情、K线、标记价格或其他用户的结果。
- 不提供批量用户点控。
- 不在当前原型中实现真实服务端接口、结算或资金入账。

## 4. 名词定义

| 名词 | 定义 |
| --- | --- |
| 用户点控 | 针对单个用户设置交易结果方向 |
| 用户点控 | 从用户管理入口一次设置该用户的交割、永续、现货三个交易模块 |
| 模块点控 | 从业务模块入口只设置该用户在当前模块的规则 |
| 一次性控制 | 历史兼容状态；当前点控弹窗不再新增一次性控制 |
| 永久控制 | 持续作用于符合条件的结算，直到管理员取消或被新规则覆盖 |
| 控盘类型 | 盈利或亏损，用于决定最终结果方向 |
| 控盘方式 | 盈利、做高盈利、做低盈利、亏损、做高亏损、做低亏损，用于决定控制幅度 |
| 用户点控日志 | 集中展示设置、修改、取消、覆盖、执行和失败记录的日志列表 |

## 5. 功能入口与页面结构

### 5.1 用户管理入口

用户管理列表保留一列“控盘类型”，不为交易模块分别增加状态列。

用户列表“操作”下拉菜单保留原有用户操作，用户列表只展示“点控”入口，不再单独展示“取消点控”入口。“控盘类型”仅用于展示当前盈利、亏损或未设置状态，不控制“点控”入口的展示。

用户详情、封户、调账、入金、划转等原有操作继续保留在同一个下拉菜单中。

### 5.2 模块管理入口

以下三个交易模块分别在自己的管理菜单下增加“用户点控”：

- 交割管理／用户点控
- 永续管理／用户点控
- 现货管理／用户点控

模块用户点控页面只管理当前模块，但可查看用户当前规则、规则来源、状态、更新时间及相关日志。

### 5.3 用户点控日志入口

菜单和页面固定命名为“用户点控日志”。操作日志和执行日志合并为一个日志列表，通过“日志类型”区分记录，不设置两个独立页面。

## 6. 用户管理用户点控

### 6.1 设置内容

管理员从用户管理点击“点控”后，在弹窗内设置：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 目标用户 | 是 | 自动带入当前用户，只读展示用户名、UID和邮箱 |
| 控盘类型 | 是 | 盈利或亏损；新建点控时默认选择亏损 |
| 控盘方式 | 是 | 根据控盘类型展示对应选项：盈利、做高盈利、做低盈利，或亏损、做高亏损、做低亏损 |
| 控盘力度 | 是 | 以百分比范围填写，默认 `1 ~ 10%`；各模块按自身口径换算具体价格偏移或结算结果 |
| 影响模块 | 自动展示 | 固定展示交割、永续、现货，不允许在用户点控设置时取消选择某个模块 |
| 点控备注 | 是 | 记录点控原因，最多200字 |

### 6.2 保存规则

1. 保存后，新规则同时写入交割、永续、现货三个交易模块。
2. 三个交易模块使用同一个控盘类型和控盘方式，规则默认长期生效。
3. 如果三个交易模块原来存在不同规则，新用户点控设置覆盖三个交易模块原有规则。
4. 被覆盖规则不删除，进入历史记录并标记为“已覆盖”。
5. 三个交易模块必须全部保存成功才算本次操作成功。
6. 任一交易模块保存失败时，本次用户点控设置整体失败，三个交易模块全部保持操作前状态，并生成失败日志。

### 6.3 修改规则

对已有点控规则的用户再次进行用户点控，视为修改：

- 三个交易模块当前有效规则全部被新规则覆盖。
- 原规则进入已覆盖历史。
- 新规则默认长期生效。
- 模块此前存在的独立规则也会被本次用户点控设置覆盖。

### 6.4 取消规则

从用户管理点击“点控”进入设置弹窗后，控盘类型选择“正常”表示恢复该用户为正常结算，并执行取消当前有效点控规则：

- 取消该用户交割、永续、现货三个交易模块中所有当前有效规则。
- 取消流程会检查三个交易模块的当前规则，不区分规则来自用户点控设置还是当前模块点控。
- 已执行、已取消和已覆盖的历史记录不重复处理。
- 取消完成后记录一次用户点控取消日志。
- 若部分模块已经没有有效规则，只取消其余仍有效的模块。
- 若没有任何有效规则，选择“正常”后仅关闭设置弹窗，不产生重复取消记录。

## 7. 模块独立点控

### 7.1 设置规则

管理员从某个业务模块的“用户点控”页面设置规则时：

1. 只修改当前模块。
2. 其他模块的规则、状态和更新时间保持不变。
3. 当前模块原有规则进入已覆盖历史。
4. 当前模块的新规则来源显示为“当前模块点控”。
5. 用户详情中标记该用户“存在模块差异”。

例如：用户原来三个交易模块均为长期盈利点控，在永续模块单独设置为长期亏损后，只有永续变为亏损，交割和现货继续保持原来的盈利规则。

### 7.2 取消规则

从模块页面点击“取消”时，只取消当前模块的有效规则，其他模块保持不变。

### 7.3 与用户点控的关系

- 模块点控可以覆盖该模块从用户管理继承的用户点控规则。
- 用户管理后续再次用户点控设置时，会覆盖包括模块独立规则在内的三个交易模块当前规则。
- 规则来源用于解释当前规则是用户点控设置还是模块点控；当前新规则默认长期生效。

## 8. 控盘类型、控盘方式与生效规则

### 8.1 控盘类型

| 控盘类型 | 交易模块结果 | 理财模块结果 |
| --- | --- | --- |
| 盈利 | 最终结果为盈利 | 收益按提高收益方向处理 |
| 亏损 | 最终结果为亏损 | 收益按低收益或最低收益方向处理 |

### 8.2 控盘方式

| 控盘类型 | 控盘方式 | 交易模块含义 | 理财模块含义 |
| --- | --- | --- | --- |
| 盈利 | 盈利 | 默认盈利 | 默认收益或正常偏高收益 |
| 盈利 | 做高盈利 | 盈利金额偏高 | 高收益 |
| 盈利 | 做低盈利 | 盈利金额偏低 | 低收益但仍按收益入账处理 |
| 亏损 | 亏损 | 默认亏损 | 低收益或最低收益 |
| 亏损 | 做高亏损 | 亏损金额偏高 | 最低收益；如产品支持亏本金，再按产品规则处理 |
| 亏损 | 做低亏损 | 亏损金额偏低 | 低收益；不默认扣本金 |

控盘方式只表示控制幅度，不代表固定金额或固定比例。各模块必须在产品配置和业务允许范围内计算具体结果。

### 8.3 生效规则

当前点控弹窗不展示“控制周期”字段。管理员确认设置后，系统按长期生效规则保存：

- 设置成功后显示“生效中”。
- 后续每次符合条件的最终结算均按当前有效规则执行。
- 单次执行成功不会结束点控规则。
- 只有管理员取消或设置新规则覆盖时才结束。

### 8.4 历史一次性控制兼容

历史数据中如存在一次性控制规则，仍按以下规则展示和执行：

- 设置成功后显示“待执行”。
- 只作用于下一次符合条件的最终结算或实际收益入账。
- 执行并入账成功后变为“已执行”，本次控制结束。
- 执行失败或入账失败时不消耗规则，继续保持“待执行”，同时记录失败日志。
- 预估收益、实时浮盈亏、行情变化、未完成订单和重复通知不会消耗一次性控制规则。

用户点控设置的一次性控制规则按模块分别消费。例如交割模块已执行后，交割显示“已执行”，其余尚未发生有效结算的模块继续显示“待执行”。

### 8.5 永久控制

永久控制是当前点控设置的默认且唯一新增方式。

## 9. 状态设计

### 9.1 当前状态

| 状态 | 含义 | 可执行操作 |
| --- | --- | --- |
| 未设置 | 当前模块没有有效规则 | 设置 |
| 待执行 | 一次性控制规则等待下一次有效结算 | 修改、取消、查看日志 |
| 生效中 | 永久控制规则持续有效 | 修改、取消、查看日志 |

### 9.2 历史与结果状态

| 状态 | 含义 | 展示位置 |
| --- | --- | --- |
| 已执行 | 一次性控制规则已经成功作用于一次结算 | 模块列表、用户详情、用户点控日志 |
| 已取消 | 有效规则被管理员主动取消 | 模块列表、用户详情、用户点控日志 |
| 已覆盖 | 原规则被新规则替换 | 用户详情历史、用户点控日志 |
| 失败 | 设置、取消或结算执行失败 | 用户点控日志 |

当前产品界面不展示“处理中”状态。

### 9.3 状态流转

一次性控制规则：

```text
未设置 → 待执行 → 已执行
            ├→ 已取消
            ├→ 已覆盖 → 新规则进入待执行或生效中
            └→ 执行失败 → 继续待执行，并记录失败日志
```

永久控制规则：

```text
未设置 → 生效中 → 已取消
            └→ 已覆盖 → 新规则进入待执行或生效中
```

## 10. 交易模块执行规则

| 模块 | 点控内容 | 触发时点 | 具体结果计算 | 一次性控制结束条件 |
| --- | --- | --- | --- | --- |
| 交割 | 盈利、做高盈利、做低盈利、亏损、做高亏损、做低亏损 | 交割合约到期并生成最终结算结果时 | 根据订单本金、周期、产品赔率和费用计算最终盈亏，并按控盘方式控制幅度 | 一笔符合条件的交割结算成功后 |
| 永续 | 盈利、做高盈利、做低盈利、亏损、做高亏损、做低亏损 | 目标用户持仓最终平仓结算时 | 根据持仓、开平仓价格、杠杆、保证金、手续费和资金费计算最终盈亏，并按控盘方式控制幅度 | 一笔符合条件的平仓结算成功后 |
| 现货 | 盈利、亏损 | 成交完成并生成用户成交结果时 | 通过用户级成交价偏移形成目标方向，不修改公共行情和其他用户成交 | 一笔符合条件的现货成交成功后 |

### 10.1 交割

- 点控在到期结算时判断，不改变订单展示期间的公共行情。
- 盈利、做高盈利、做低盈利、亏损、做高亏损、做低亏损的具体金额由交割产品自身规则计算。
- 一次性控制规则只在最终结算成功后结束。

### 10.2 永续

- 用户点控不使用“插线”方式修改公共K线、标记价格或其他用户行情。
- 点控只在目标用户最终平仓结算时约束结果方向。
- 实时浮盈亏变化不视为规则执行，一次性控制规则不会因此结束。
- 具体盈亏由永续模块结合仓位、杠杆、费用和结算规则计算，并按控盘方式区分默认、高、低幅度。

### 10.3 现货

- 现货使用用户级成交价偏移实现点控，不修改公共行情、K线、盘口和其他用户成交价格。
- 买单盈利时使用更低成交价，亏损时使用更高成交价；卖单盈利时使用更高成交价，亏损时使用更低成交价。
- 现货不使用做高盈利、做低盈利、做高亏损、做低亏损，选择这些方式时按默认盈利或默认亏损处理。
- 一次性控制规则只有在一笔符合条件的现货成交成功后才结束。

## 11. 规则优先级

同一用户、同一模块、同一次结算同时命中多种控制规则时，按以下顺序执行：

```text
单笔订单或持仓控制
> 当前模块的用户点控
> 用户管理用户点控
> 模块全局场控
> 自然业务结果
```

补充规则：

1. 高优先级规则只影响本次最终采用结果，不删除低优先级规则。
2. 同一优先级存在多条有效规则时，采用最新设置的一条。
3. 被替换的旧规则进入“已覆盖”历史。
4. 用户点控只影响目标用户，不影响其他用户。

## 12. 用户点控日志

### 12.1 日志范围

一个日志列表集中记录以下事件：

- 用户点控设置和模块点控
- 用户点控修改和模块独立修改
- 用户点控取消和模块独立取消
- 旧规则被覆盖
- 一次性控制规则执行成功
- 永久控制规则结算执行
- 设置、取消或执行失败

### 12.2 日志字段

| 字段 | 说明 |
| --- | --- |
| 操作时间 | 设置、取消或执行发生的时间 |
| 用户 | 用户名、UID等识别信息 |
| 日志类型 | 设置、取消、执行 |
| 影响模块 | 三个交易模块或单个模块 |
| 控盘类型 | 盈利／亏损 |
| 控盘方式 | 盈利、做高盈利、做低盈利、亏损、做高亏损、做低亏损 |
| 控制周期 | 一次性控制／永久控制 |
| 规则来源 | 用户点控设置／当前模块点控 |
| 执行结果 | 成功／失败 |
| 操作人 | 执行管理操作的后台账号 |
| 业务单号 | 执行日志关联的订单、持仓或收益记录编号 |
| 备注或失败原因 | 设置原因、取消原因或失败原因 |

### 12.3 列表能力

- 支持按用户、模块、日志类型、执行结果和时间范围筛选。
- 支持分页。
- 日志只用于查询和审计，不提供修改或删除操作。

## 13. 异常与失败处理

| 场景 | 处理规则 | 用户可见结果 |
| --- | --- | --- |
| 用户点控设置任一交易模块失败 | 整次操作失败，三个交易模块全部保持原状态 | 提示设置失败；日志记录失败模块和原因 |
| 模块点控失败 | 当前模块保持原状态，其他模块不受影响 | 提示设置失败；记录失败日志 |
| 一次性控制规则执行失败 | 不结束规则，继续等待下次有效执行 | 当前状态仍为待执行；记录失败日志 |
| 永久控制规则单次执行失败 | 永久控制规则继续生效 | 当前状态仍为生效中；记录失败日志 |
| 取消失败 | 原规则继续有效 | 状态不变；记录失败日志 |
| 重复结算通知 | 不重复执行或重复结束一次性控制规则 | 保持首次成功结果 |
| 管理员并发修改 | 以最终成功提交的最新规则为准 | 旧规则进入已覆盖历史 |

## 14. 权限与操作安全

1. 只有具备用户点控权限的后台角色可以设置、修改和取消规则。
2. 查看用户点控日志可配置为独立权限。
3. 设置、修改要求填写点控备注，取消要求填写取消点控备注。
4. 所有操作必须记录操作人、时间、目标用户、影响模块和变更结果。
5. 用户点控设置、永久控制规则设置及覆盖操作可接入平台现有的敏感操作验证机制。
6. 日志不得由普通操作人员修改或删除。

## 15. 页面交互要求

### 15.1 用户列表

- 只保留一列“控盘类型”。
- “盈利”表示当前有效点控按盈利方向处理。
- “亏损”表示当前有效点控按亏损方向处理。
- “-”表示当前没有有效点控规则。
- 所有用户相关操作集中放在“操作”下拉菜单中。
- 用户列表只展示“点控”入口，不单独展示“取消点控”入口；“控盘类型”仅提供状态信息。

### 15.2 设置弹窗

- 弹窗布局保持紧凑，在常规后台屏幕高度下无需整体滚动。
- 弹窗外框固定，内容区域确需滚动时只允许内容区域滚动。
- 点击遮罩不关闭弹窗，避免误操作丢失填写内容。
- 底部固定展示“取消”和“确认设置”。
- 用户列表点控设置弹窗展示控盘类型、影响模块和点控备注；控盘类型提供“永久亏损”“永久盈利”“正常”三个选项。
- 新建点控弹窗默认选择“永久亏损”；控制周期不展示，默认长期生效。
- 用户列表点控设置弹窗不展示当前点控状态、控盘方式和控盘力度；影响模块固定展示交割合约。
- 不展示“Demo模式”“模拟工具”或仅供开发理解的说明文案。

### 15.3 模块列表

- 显示用户、控盘类型、控盘方式、状态、规则来源和更新时间。
- 操作提供设置或修改、取消、日志。
- 未设置用户不可执行取消。
- 待执行和生效中的用户可以修改或取消。

### 15.4 日志列表

- 页面名称固定为“用户点控日志”。
- 设置、取消和执行记录在同一张表中。
- 成功与失败使用清晰状态标识。
- 列表必须提供分页。

## 17. 验收标准

### 17.1 用户管理

- 用户列表只显示一列“控盘类型”。
- 操作下拉菜单保留原有用户操作。
- 无论是否存在有效规则，操作下拉菜单均显示“点控”入口。
- 已开启点控的用户，可在点控弹窗选择“正常”恢复正常结算。
- 可以从用户点控设置交割点控。
- 可以从用户管理用户点控取消三个交易模块当前有效规则。

### 17.2 模块管理

- 交割、永续、现货三个交易模块均有独立的“用户点控”菜单和页面。
- 模块点控只影响当前模块。
- 模块独立取消只取消当前模块。
- 模块设置后，其他模块的规则和状态不变。

### 17.3 控制规则

- 盈利类控盘方式在交易模块为盈利结果。
- 亏损类控盘方式在交易模块为亏损结果。
- 一次性控制规则成功执行后变为已执行。
- 一次性控制规则执行失败后继续待执行。
- 永久控制规则执行后继续生效，直到取消或覆盖。

### 17.4 原子性与历史

- 用户点控设置任一交易模块失败时，三个交易模块全部保持原状态。
- 新用户点控设置会覆盖三个交易模块当前规则。
- 被替换规则可在历史或日志中查询。
- 模块独立规则可被后续用户点控设置覆盖。

### 17.5 日志

- 设置、取消和执行使用同一个“用户点控日志”列表。
- 日志同时包含成功和失败记录。
- 日志支持筛选和分页。
- 失败日志显示失败模块或业务对象及失败原因。

## 18. 开发与测试规则附录

### 18.1 最低规则信息

每条模块规则至少需要保存：规则编号、批次编号、用户、模块、控盘类型、控盘方式、模块控制值、当前状态、规则来源、点控备注、设置时间，以及执行、取消或覆盖时间。当前新增规则默认长期生效；如系统需兼容历史一次性规则，可继续保留控制周期字段用于历史展示和执行判断。

### 18.2 一致性要求

1. 用户点控设置的三条交易模块规则使用同一批次编号。
2. 三个交易模块写入与失败回滚必须作为一个不可拆分的操作。
3. 一次性控制规则的成功执行记录和规则结束必须同步完成。
4. 执行失败只写失败日志，不修改一次性控制规则的有效状态。
5. 同一业务单号不得重复成功消费一次性控制规则。
6. 结算执行时应读取最新有效规则，避免使用已取消或已覆盖规则。

### 18.3 日志保留要求

- 当前规则被修改时，必须保留修改前内容。
- 日志应能追溯一次用户点控设置涉及的全部模块。
- 日志应能定位实际使用的规则和关联业务单号。
- 失败记录不得覆盖或替换成功记录。

### 18.4 原型与正式系统边界

当前项目为界面原型，使用前端数据演示操作和状态变化。正式系统需要另行实现权限校验、服务端持久化、原子写入、失败回滚、结算接入、资金入账和不可篡改的审计日志。
