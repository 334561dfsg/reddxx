# 量化基金管理后台（2026-11-27）

前台 AI 量化 → 量化基金（`/NewQuantCapital/ai-quant/quant-fund`）的后台，独立分组「量化基金」，路由 `/admin/quant-fund/*`。旧的「AI量化交易」（`/admin/ai-quant/*`，固定收益产品）保持不变，两者不是一套数据。

## 用户决定

- 新建独立分组，不改造旧的 AI量化交易。
- 活期赎回需要后台审核：用户提交后订单进入「赎回审核中」，审核期间继续派息；通过后返还本金，拒绝后恢复持有。
- 每日派息按产品配置的日收益率区间随机：每满一天派息一次，当日收益率在上下限之间随机（按订单号 + 日期确定，刷新不变）。前台展示区间平均值。
- Mock 为页面内静态数据（与借贷、策略相同），刷新即重置，不做浏览器持久化。

## 页面

| 菜单 | 路由 | 内容 |
|---|---|---|
| 产品管理 | `/admin/quant-fund/products` | 列表（名称/代码/期限类型/状态搜索、日收益率区间与前台展示值、申购金额、募集进度、持有中、排序权重、上下架）+ 单页分组编辑器 |
| 申购订单 | `/admin/quant-fund/orders` | 审核（通过开始计息 / 拒绝退回本金）、详情、派息、记录 |
| 赎回审核 | `/admin/quant-fund/redemptions` | 待审核赎回的通过 / 拒绝，历史只读 |
| 派息记录 | `/admin/quant-fund/payouts` | 每日派息流水：日期、订单、用户、本金、日收益率、派息金额 |
| 操作日志 | `/admin/quant-fund/logs` | 申购、审核、赎回、到期结算、产品保存与上下架 |

页面沿用 AI 策略后台约定：查询卡片一个字段一个输入框；记录表一列一个字段、单行、可横向滚动；审核/详情用弹窗，单笔订单的派息与操作记录用抽屉；用户 ID 打开共享用户抽屉；排序权重数值越大越靠前；操作反馈用 toast。

## 产品字段

基本信息（名称、代码、标识币种、风险等级、策略标签、描述、排序权重）；申购条件（最低认证等级、最低 VIP 等级，同时满足）；期限与额度（活期/定期切换保留另一类型草稿；定期期限天数、活期最短持有天数；起投金额、单笔上限、产品总额度、初始募集比例）；每日收益规则（日收益率下限/上限）。

- 标识币种（USDT / USDC / BTC / ETH / SOL）只用于前台卡片图标和资产筛选，申购、派息、赎回一律用 USDT（用户决定，2026-11-27）；申购时随条款冻结到订单。
- 标签颜色按类型决定，后台不配置颜色：风险等级按等级着色（低绿、中品牌色、高橙、极高红），活期产品自动带高亮「活期 / 随时赎回」，策略标签是自由输入的文字、统一灰色；编辑页有「前台标签预览」。
- 募集进度与剩余额度 = 初始募集（总额度 × 比例）+ 持有中与赎回审核中的本金；审核通过时再检查一次额度。
- 产品保存按版本校验，记录前后差异；新产品默认未上架，保存不改变上下架状态。
- 订单在申购时冻结产品条款（期限、最短持有、日收益率区间），之后修改产品不影响已有订单。

## 订单状态

`pending_review` →（通过）`active` →（活期申请赎回）`redeem_pending_review` →（通过）`redeemed` /（拒绝）`active`；定期到期自动 `settled`（返还本金，利息已按日派发）；`pending_review` →（拒绝）`rejected`（退回本金）。下架产品不能新申购，待审核申购也不能通过；持有中订单继续派息、赎回和到期。

## 共享模块

`src/shared/quantFund/{domain,seed,service,client}.js`。种子是 6 个 VIP 档位产品（来自前台目录，日收益率区间为公布值 ±20%，最低 VIP 等级等于档位），以及按时间顺序通过真实命令回放的 4 个模拟用户订单历史，覆盖全部订单与赎回状态。测试：`test/quantFundDomain.test.js`。

## 前台改动

活期「贖回」改为提交审核：确认弹窗显示审核说明，成功后提示「贖回申請已提交」，订单变为「贖回審核中」。前台仍是自己的本地账本，与后台不共享实时状态，因此前台的赎回申请会一直停在审核中。
