# C2C 交易后台（2026-11-27）

前台 金融 → C2C（`/NewQuantCapital/c2c/*`）的后台，独立分组「C2C 交易」，路由 `/admin/c2c/*`。

## 用户决定

- 去掉收款账户功能：前台买单和卖单直接提交到后台，进入「待审核」，付款与打款在线下完成。
- 后台「通过」：买单为用户入账所买币种；卖单在提交时已冻结币，通过后扣除冻结（平台线下打款 USDT）。「拒绝」：买单不动余额；卖单解冻退回可用。
- 用户可以取消自己的待审核订单；取消卖单解冻资产。
- 后台增加「报价管理」：按币种和方向配置价格、单笔限额、报价有效期、备注、启用开关和排序权重。前台仍用自己的静态报价，不与后台实时同步。
- Mock 为页面内静态数据（与借贷、量化基金相同），刷新即重置，不做浏览器持久化；前台与后台各自一份数据。

## 页面

| 菜单 | 路由 | 内容 |
|---|---|---|
| 订单审核 | `/admin/c2c/orders` | 订单号 / 用户 ID / 方向 / 币种 / 状态查询；待审核订单「审核」（通过 / 两步拒绝），其他「详情」只读；用户 ID 打开共享用户抽屉 |
| 报价管理 | `/admin/c2c/quotes` | 报价列表（价格、单笔限额、有效期、备注、待审核订单数、状态、排序权重）；启用 / 停用确认；新增与编辑为单页分组表单 |
| 操作日志 | `/admin/c2c/logs` | 提交、通过、拒绝、取消、保存报价、启用 / 停用报价，自动生成说明，记录操作人 |

沿用 Earn / 量化基金后台约定：查询卡片一个字段一个输入框；记录表一列一个字段、单行；审核用弹窗，不填写操作原因；操作反馈用 toast；审核人为模拟身份。

## 规则

- 订单状态：`pending_review` →（通过）`completed` /（拒绝）`rejected` /（用户取消）`cancelled`。只有待审核订单可以操作，重复处理被拒绝。
- 下单时校验报价已启用、数量在单笔限额内；卖单校验可用余额并冻结。订单冻结下单时的报价（价格、限额、版本），之后改报价不影响已有订单。
- 报价按「币种 + 方向」唯一；保存按版本校验并记录前后差异；新报价默认停用，保存不改变启用状态；停用不影响已提交的待审核订单。
- 每个命令先在副本上执行，全部校验通过才提交；同一 requestId 不能重复提交。

## 共享模块

`src/shared/c2c/{domain,seed,service,client}.js`。种子是前台的 6 条报价（买：ETH、USDC、BTC、USDT、SOL；卖：USDT）和 4 个模拟用户的 17 笔订单历史，按时间通过真实命令回放，覆盖全部状态，余额与冻结一致。测试：`test/c2cDomain.test.js`。
