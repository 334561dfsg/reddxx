# 用户点控状态流转与模块执行规则

## 1. 文档目的

本文档定义单个用户点控在六个业务模块中的统一状态、流转条件、覆盖优先级、失败处理和日志要求。当前项目是前端 Demo，Mock 数据用于演示所有关键状态；服务端开发应按本文档实现真实持久化、事务和结算接入。

## 2. 设计原则

1. 管理员只设置方向，不直接填写金额、价格、收益率或收益金额。
2. 交易模块使用“盈利／亏损”，理财模块使用“高收益／低收益”。
3. 用户管理中的统一设置覆盖六个模块现有规则，必须保证原子性。
4. 模块菜单中的独立设置只覆盖当前模块，其他五个模块保持不变。
5. 单次生效规则只在真实最终结算或实际收益入账成功后结束。
6. 失败不消费单次生效规则，也不得错误修改当前有效规则。
7. 长期生效规则持续生效，直到管理员取消或被新规则覆盖。

## 3. 状态定义

### 3.1 当前状态

| UI 状态 | 数据条件 | 说明 | 允许操作 |
| --- | --- | --- | --- |
| 未设置 | 当前模块没有规则，或没有有效规则 | 当前没有用户点控 | 设置 |
| 待执行 | `status=active` 且 `duration=once` | 等待下一次符合条件的真实结算 | 修改、取消 |
| 生效中 | `status=active` 且 `duration=permanent` | 持续作用于后续符合条件的结算 | 修改、取消 |

前端 Demo 不使用“处理中”。真实服务端如需内部处理中状态，可作为技术状态保存，但不应成为管理员必须理解的业务状态。

### 3.2 历史结果

| UI 状态 | 数据状态 | 产生条件 | 是否仍有效 |
| --- | --- | --- | --- |
| 已执行 | `consumed` | 单次生效规则成功影响一次最终结算 | 否 |
| 已取消 | `cancelled` | 管理员取消有效规则 | 否 |
| 已覆盖 | `superseded` | 当前规则被新规则替换 | 否，只保留历史 |
| 失败 | 日志 `status=failed` | 设置或执行失败 | 规则保持失败前状态 |

## 4. 核心状态流转

### 4.1 单次生效规则

```text
未设置 ──设置单次生效规则──> 待执行
待执行 ──最终结算成功──> 已执行
待执行 ──管理员取消──> 已取消
待执行 ──设置新规则──> 旧规则已覆盖 + 新规则待执行/生效中
待执行 ──结算执行失败──> 待执行 + 失败日志
```

不会消费单次生效规则的情况：预估收益变化、实时浮盈亏变化、行情变化、订单未最终成交、结算回滚、收益入账失败、无效或重复结算事件。

### 4.2 长期生效规则

```text
未设置 ──设置长期生效规则──> 生效中
生效中 ──任意次数结算成功──> 生效中
生效中 ──管理员取消──> 已取消
生效中 ──设置新规则──> 旧规则已覆盖 + 新规则待执行/生效中
```

### 4.3 统一设置

统一设置以六模块为一个事务批次：

```text
全部成功：六模块旧规则进入已覆盖历史 → 六模块写入同一 batchId 的新规则
任一失败：六模块全部保持原状态 → 记录失败模块和失败原因 → 不生成部分成功规则
```

统一取消只取消六模块中当前有效的规则；已执行、已取消和已覆盖历史不重复修改。

### 4.4 模块独立设置

模块独立设置只替换目标模块：

- 目标模块原规则进入“已覆盖”历史。
- 目标模块写入 `source=module` 的新规则。
- 其他五个模块保持原规则、状态和更新时间。
- 用户详情显示“存在模块差异”。

模块独立取消只取消目标模块。用户管理中的统一取消则取消六个模块的当前有效规则。

## 5. 六模块执行规则

| 模块 | 点控内容 | 触发时点 | 模块自行计算内容 | 单次生效何时结束 |
| --- | --- | --- | --- | --- |
| 交割 | 盈利／亏损 | 交割合约到期并生成最终结算结果时 | 根据订单本金、周期、产品赔率及费用计算最终盈亏金额 | 目标用户一笔符合条件的交割结算成功后 |
| 永续 | 盈利／亏损 | 目标用户持仓最终平仓结算时 | 根据持仓、开平仓价格、杠杆、保证金、手续费及资金费计算最终盈亏 | 一笔符合条件的平仓结算成功后 |
| 现货 | 盈利／亏损 | 卖出成交完成、原始净盈亏计算完成并进行最终结算时 | 保留真实成交计算的原始净盈亏，通过独立损益调整形成最终目标方向 | 原始结果与损益调整均成功入账后 |
| AI量化 | 高收益／低收益 | 产品周期结算或实际收益入账时 | 在产品允许的收益区间内计算该用户本期收益 | 一次实际收益成功入账后 |
| 流动性挖矿 | 高收益／低收益 | 挖矿周期结算或收益领取入账时 | 按产品规则、参与金额、周期及允许收益档位计算收益 | 一次实际收益成功入账后 |
| 投资组合 | 高收益／低收益 | 组合周期结算、赎回结算或收益入账时 | 按组合净值、持有份额、周期及产品收益边界计算收益 | 一次实际收益成功入账后 |

### 5.1 永续模块特别说明

用户点控不通过“插线”修改全局 K 线、标记价格或其他用户行情，也不直接修改实时浮盈亏。它只在目标用户最终平仓结算时约束结果方向，由永续模块在合规边界内计算具体金额。

### 5.2 现货模块特别说明

现货成交继续使用真实大盘价格。卖出后先生成不可修改的原始交易净盈亏，再以独立损益调整记录形成最终结算净盈亏。盈利控制可产生平台补贴，亏损控制可产生平台扣减；只有调整成功入账且最终方向满足规则时才算执行成功。调整失败不消费单次生效规则。

### 5.3 理财模块特别说明

“高收益／低收益”是产品允许范围内的收益档位，不等于保证固定收益。具体收益率、收益金额、费用和舍入方式由对应模块计算，点控层只提供目标方向。

## 6. 优先级

交易类模块按以下顺序决定最终结果：

```text
单笔订单/持仓控制 > 模块用户点控 > 用户管理统一点控 > 模块全局场控 > 自然结果
```

说明：

- 模块独立设置覆盖该模块从用户管理继承的统一设置。
- 用户点控只影响目标用户，不改变其他用户结果。
- 低优先级规则仍保留，但本次结算不采用。
- 同一优先级下，使用最新有效规则；旧规则进入“已覆盖”历史。

## 7. 数据与日志要求

### 7.1 当前规则最低字段

| 字段 | 说明 |
| --- | --- |
| `id` | 模块规则唯一标识 |
| `batchId` | 六模块统一设置批次；模块独立设置可为空 |
| `userId` | 目标用户 |
| `moduleKey` | 目标模块 |
| `value` | `profit/loss/highYield/lowYield` |
| `duration` | `once/permanent` |
| `status` | `active/consumed/cancelled`；覆盖规则进入历史表 |
| `source` | `global/module` |
| `note` | 管理员必填备注 |
| `updatedAt` | 最近设置时间 |
| `consumedAt` | 单次生效执行成功时间 |
| `cancelledAt` | 取消时间 |

### 7.2 已覆盖历史

被替换的规则必须完整复制到历史记录，标记 `status=superseded` 和 `supersededAt`，不得直接覆盖后丢失原规则。

### 7.3 操作日志

设置和取消日志至少记录：操作时间、操作人、用户、模块范围、规则来源、生效方式、批次号、变更前快照、变更后摘要、成功／失败、备注、失败模块和失败原因。

### 7.4 执行日志

结算执行日志至少记录：用户、模块、规则 ID、业务单号、规则来源、生效方式、执行前结果、目标结果、成功／失败、失败原因和执行时间。

成功执行单次生效规则时，规则状态和执行日志必须在同一事务中提交。执行失败时只写失败日志，规则继续保持 `active`。

## 8. 幂等与并发要求

1. 同一业务单号只能成功消费一次规则。
2. 结算开始时必须重新读取最新有效规则，不能使用过期缓存直接结算。
3. 单次生效规则的“写执行日志 + 改为已执行”必须原子提交。
4. 统一设置必须锁定用户的六模块规则或使用同等效果的事务方案。
5. 取消、覆盖和结算并发时，以服务端事务提交顺序为准，并在日志中保留最终采用的规则 ID。

## 10. 验收清单

- 模块列表能看到未设置、待执行、生效中、已执行和已取消。
- 用户详情能看到六模块同步、部分已执行、模块差异和已覆盖历史。
- 用户点控日志能看到设置成功、取消成功、执行成功、设置失败和执行失败。
- `user_1005` 失败设置前后的六模块批次和规则一致。
- `user_1006` 执行失败后交割规则仍为待执行。
- Demo 和正式实现均不把预估数据变化当作单次生效规则消费条件。
