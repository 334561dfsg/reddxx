# 用户长列表抽屉固定控制区设计

## 目标

统一用户管理中长列表抽屉的滚动模型：抽屉标题、搜索/筛选控制和分页保持可见，仅列表或明细区域滚动。解决当前滚动较长内容后无法快速调整筛选或翻页的问题，同时遵守现有 Drawer 的模态、焦点、动画、安全区域和低高度视口约束。

## 范围

本次处理以下已有分页列表：

- `UserRelationshipDrawer`：直属裂变下级、全部裂变下级共用的成员列表。
- `UserTeamReportDrawer`：直属裂变分支明细。
- `UserAgentReportDrawer`：代理业绩明细。

同时检查用户操作抽屉中使用同类“长列表 + 分页”结构的组件；只有具备分页且会产生长列表的区域纳入本次改造。无分页的普通表单、详情内容和审核列表不改变滚动模型。

## 统一布局

抽屉保持单一固定外框和四段结构：

1. 固定标题区：标题、用户上下文和关闭按钮。
2. 固定上下文区：当前列表直接相关的搜索、筛选或明细标题；没有搜索筛选时保留简洁的分区标题与数量说明。
3. 主滚动区：仅渲染当前页列表卡片或空状态，使用 `min-height: 0`、`overflow-y: auto` 和受控 overscroll。报表抽屉允许在主滚动区上方增加一个边界清晰、受限高度的概览滚动区，使完整概览可达且不挤掉明细列表。
4. 固定分页区：位于抽屉底部，包含数量与翻页控件，并处理底部与左右安全区域。

搜索、筛选和分页不得放进滚动容器。分页不足一页时仍允许组件按既有规则只显示总数、不显示多余翻页按钮，底部区域高度保持稳定。

## 各抽屉处理

### 裂变成员列表

- 搜索输入框、账户状态和用户角色筛选整体固定在列表上方。
- 当前页成员卡片单独滚动。
- 分页固定在底部。
- 搜索或筛选变化重置到第 1 页；数据缩减时页码继续按既有逻辑收敛。
- 筛选无结果的空状态显示在滚动区，不使控制区或分页跳位。

### 裂变团队报表

- 团队概览指标放在上方可滚动的报表概览区域；直属裂变分支进入独立的明细分区。
- 分支明细标题固定在其列表上方，分支卡片是主要滚动列表，分页固定在抽屉底部。
- 在低高度视口中，概览区域限制最大高度并可自身滚动，保证分支列表仍有可操作空间；不得导致关键指标不可达。
- 无团队成员时，空状态占据主内容区，不显示无意义分页。

### 代理业务报表

- 业务概览和产品线汇总位于上方受限高度的报表概览区域，可滚动查看全部内容。
- 代理业绩明细标题固定在明细列表上方，日期卡片单独滚动，分页固定在底部。
- 加载错误和整份报表为空时使用主内容区展示，不保留无意义的空分页。
- 仅业绩明细为空时，概览仍可查看，明细区显示稳定空状态。

## 响应式与可访问性

- 抽屉外框始终 `overflow: hidden`，不得恢复为整个抽屉滚动。
- 固定区域使用 `shrink-0`；滚动区域使用 `min-h-0 flex-1 overflow-y-auto overscroll-y-contain`。
- 低高度视口优先压缩间距和限制概览区最大高度，不隐藏搜索、筛选、分页或关闭按钮。
- 移动端允许筛选项换行；不得产生必须双向滚动的布局。
- 四向安全区域继续覆盖标题、内容和分页；分页中的按钮保持键盘可达和足够触摸目标。
- 搜索词、筛选条件、当前页及当前抽屉实例在窗口尺寸变化时保持不丢失。
- 遮罩不可关闭、Escape、焦点约束、背景隔离、动画和关闭后的焦点返回沿用现有共享 Drawer 生命周期，不改变业务语义。

## 测试与验收

- 组件测试断言每个抽屉只有设计中明确的滚动区：成员列表只有一个主滚动区，报表最多包含一个概览滚动区和一个明细主滚动区；搜索/筛选和分页位于主滚动区之外。
- 裂变成员列表验证搜索、筛选、翻页、空状态和数据缩减后的页码收敛。
- 两类报表验证概览内容完整、明细列表滚动、分页固定，以及整份为空和仅明细为空的状态。
- 源码契约测试覆盖 `overflow-hidden` 外框、`min-h-0`、`overflow-y-auto`、安全区域和既有 Drawer 动画规则。
- 运行相关组件测试、完整 `npm test`、生产构建和 `git diff --check`。
- 浏览器人工验收应覆盖 `1440×900`、`1280×720`、平板、窄屏与低高度手机、200% 缩放、键盘/触摸、动态视口、四向安全区域和 Reduced Motion；未执行项必须明确报告。

## 非目标

- 不修改分页每页 10 条的业务规则。
- 不新增后端接口或改变报表数据结构。
- 不将抽屉改造成独立路由页面。
- 不改造没有分页的普通表单、详情和审核列表。
