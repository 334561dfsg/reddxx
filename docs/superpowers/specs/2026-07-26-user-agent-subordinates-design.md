# 用户代理下级列表设计

## 目标

在 `/admin/users/list` 的“用户操作”Drawer 中，为代理用户补充独立的“查看下级用户”入口，让运营能够查看归属于该一级代理的具体客户，而不把代理归属关系误当作裂变邀请关系。

## 业务口径

- 代理下级是后台代理归属关系中的一级直属客户，不递归包含裂变后代，也不包含下级代理层级。
- “查看直属裂变下级”和“查看全部裂变下级”继续表达邀请裂变关系，不能作为代理下级名单的替代入口。
- “查看代理报表”继续展示业务和佣金汇总；具体客户名单由新的独立入口承载。
- 入口仅对 `role === 'agent'` 或兼容字段 `isAgent === true` 的用户显示，普通用户不显示空入口。

## 操作入口

“代理管理”分组按以下顺序展示：

1. 设置为代理；代理用户显示取消代理身份。
2. 查看下级用户，仅代理用户显示，说明为“查看归属于该代理的直属客户”。
3. 查看代理报表，仅代理用户显示。

桌面维持两列、窄屏维持一列。入口保持一次点击可达，不增加 Tab，也不关闭父级“用户操作”Drawer。

## 数据与仓储

新增用户级代理下级仓储接口，按代理用户 ID 返回隔离副本。每条记录包含：

- 稳定记录 ID。
- UID 与用户名。
- 注册时间。
- 用户状态：活跃、暂停或禁用。
- 累计业务量，单位 USDT。
- 累计佣金贡献，单位 USDT。

演示数据必须由代理用户 ID 确定性生成，不同代理的数据相互隔离；同一代理重复读取结果一致。接口拒绝空用户 ID，调用方捕获失败并将文本错误交给 Drawer 展示。后续替换为后端接口时保持相同返回结构。

## 下级用户 Drawer

新建独立右侧模态 Drawer，标题为“代理下级用户”，副标题显示用户名和 UID。打开时父级“用户操作”Drawer 保持挂载，新的 Drawer 成为唯一可交互的最上层。

Drawer 内容包括：

- 结果摘要，显示当前筛选结果数。
- 搜索框，可按 UID 或用户名进行本地、即时、不区分大小写的搜索。
- 状态筛选，选项为全部、活跃、暂停、禁用。
- 下级用户卡片列表；窄屏保持单列，不引入横向滚动。
- 每页 10 条的统一紧凑分页。

搜索或状态变化时回到第一页；结果缩减导致页码越界时收敛到最后一个有效页；切换代理、关闭后重新打开时回到第一页。无数据时显示“该代理暂无下级用户”，筛选无结果时显示“没有符合当前条件的下级用户”。

## Drawer 生命周期与无障碍

- Teleport 到应用根层，遮罩覆盖完整视口且点击遮罩不关闭。
- 外框不滚动，仅内容区纵向滚动；标题和右上角 `aria-label="关闭"` 按钮固定可见。
- 使用 `role="dialog"`、`aria-modal="true"` 和可见标题关联的 `aria-labelledby`。
- 打开后聚焦标题；Tab 和 Shift+Tab 限制在最上层 Drawer；Escape 关闭最上层 Drawer。
- 打开和关闭分别使用 `200ms ease-out` 与 `150ms ease-in` 的右侧平移动画；Reduced Motion 取消位移并限制为不超过 50ms 的淡入淡出。
- 关闭动画完成后才卸载 DOM、释放当前实例的背景隔离、滚动锁和焦点约束，并恰好一次返回到“查看下级用户”入口。
- 请求失败时 Drawer 保持打开，错误文本可聚焦，并提供键盘可达的重试按钮；重试不产生重复请求。
- 组件卸载或路由切换时立即处置当前实例，旧回调不能影响新路由或其他存活浮层。

## 测试与验收

- 配置测试覆盖代理用户入口顺序、标题、处理器和普通用户隐藏行为。
- 仓储测试覆盖空 ID、确定性、用户隔离、返回副本和字段结构。
- 组件测试覆盖搜索、状态筛选、分页、页码重置与收敛、空状态、错误及重试。
- 页面集成测试覆盖入口派发、父 Drawer 保持挂载、数据读取、失败状态、关闭清理和焦点返回。
- Drawer 生命周期测试覆盖遮罩抵抗、固定框架、语义、焦点、关闭顺序、动画、Reduced Motion 和叠层隔离。
- 运行相关 Node 测试、全量测试和生产构建。
- 真实浏览器中未执行的桌面、平板、窄屏、低高度、200% 缩放、键盘、鼠标、触摸、虚拟键盘、安全区域、高对比度、长文本及断点切换检查必须明确报告为未验证。
