# 用户操作入口中心设计

## 目标与范围

在后台「用户管理 / 用户列表」补齐客户现有系统中的用户操作入口，同时避免把二十余个动作堆叠在表格下拉菜单中。

本阶段只完成入口、信息架构、交互状态和现有功能复用。尚无业务实现的动作必须明确标记为「待接入」，不得模拟成功、修改用户数据或产生虚假的操作日志。

## 现状对照

当前用户列表已有以下操作：

- 用户详情
- 封户／解封
- 调账
- 入金
- 划转
- 统一点控
- 取消点控
- 点控日志

参考系统还包含以下入口：

- 查看直属下级、查看全部下级、重设上级、设置／重设代理、查看团队报表
- 资金概况、链上钱包、冻结全部资金、解冻全部资金、划扣可用资金、客服入金、出金流水限制、后台划扣记录、手动上分地址
- 编辑资料、信用分审核、修改信用分、添加返利奖励、编辑会员等级、会员累计充值

语义合并规则：

- 「资金概况」优先复用用户详情中的资产信息，但保留独立快捷入口并直接定位资产内容。
- 「客服入金」复用当前「入金」能力，统一对外名称为「客服入金」。
- 「划扣正常资金」统一命名为「划扣可用资金」。
- 「当前会员等级累计充值 USDT」统一命名为「会员累计充值」。
- 当前「封户／解封」是账户状态操作，不等同于「冻结／解冻全部资金」，两组入口同时保留。

## 方案选择

采用「快捷操作菜单 + 全部操作右侧面板」的混合方案。

不采用单个长菜单：动作数量超过单层菜单适合承载的范围，低高度视口下容易溢出，危险动作也难以形成稳定分区。

不把所有动作塞入用户详情：列表场景中的高频操作会多一次跳转或打开步骤，且详情内容与操作入口混杂。

## 表格快捷操作菜单

现有「操作」按钮继续作为唯一表格入口，打开后展示：

1. 用户详情
2. 资金概况
3. 客服入金
4. 调账
5. 封户／解封
6. 全部操作…

菜单遵循以下规则：

- 快捷项保持固定顺序，不随用户状态重新排序；只替换「封户／解封」的文案。
- 选择动作后立即关闭菜单。
- `Escape`、点击菜单外部或选择菜单项可关闭非模态菜单。
- 支持键盘聚焦、可访问名称和方向键／Tab 可达性；打开面板后焦点进入面板。
- 表格行点击打开用户详情，但菜单按钮及菜单内容必须阻止行点击冒泡。

## 全部操作面板

「全部操作…」打开从右侧进入的模态 Drawer。面板标题为「用户操作」，副标题展示用户名和 UID。

面板按以下顺序分组：

### 用户与关系

- 编辑资料
- 查看直属下级
- 查看全部下级
- 重设上级
- 设置／重设代理
- 查看团队报表

### 资金与钱包

- 资金概况
- 链上钱包
- 客服入金
- 账户划转
- 冻结全部资金
- 解冻全部资金
- 划扣可用资金
- 出金流水限制
- 后台划扣记录
- 手动上分地址

### 信用与会员

- 信用分审核
- 修改信用分
- 编辑会员等级
- 会员累计充值
- 添加返利奖励

### 风控与控制

- 封户／解封
- 统一点控
- 取消点控
- 点控日志

入口采用带标题和简短说明的操作卡片。宽屏使用两列，窄屏使用单列。危险或敏感动作放在所在分组末尾，使用警示图标和颜色，但不让颜色成为唯一语义提示。

## 功能状态与数据流

每个入口由统一配置描述，至少包含：标识、标题、说明、分组、状态、风险级别和处理器。

状态分为：

- `available`：已有功能，点击后复用当前 Drawer、Dialog 或路由。
- `planned`：入口已设计但业务未接入，显示「待接入」徽标。
- `unavailable`：因用户状态不满足而不可执行，显示明确原因。

本阶段 `planned` 项可聚焦和点击；点击后在面板内显示非阻塞说明「该功能入口已预留，业务能力待接入」，不打开空白弹窗，也不产生数据变更。说明区域使用可访问的状态文本。

已有能力的映射：

- 用户详情、资金概况 → `UserDetailDrawer`
- 客服入金、调账、账户划转、封户／解封 → `UserOperations` 内现有动作
- 统一点控、取消点控 → 当前用户统一控制流程
- 点控日志 → `users-control-log` 路由并携带 `userId`

从操作面板打开已有 Dialog 时，操作面板作为下层保持挂载且不可交互；关闭顶层 Dialog 后焦点回到触发卡片。打开用户详情或跳转日志等同级流程时，先完成操作面板关闭动画，再打开目标界面或导航，避免两个 Drawer 同时争夺焦点。

## Drawer 交互与可访问性

- 使用应用根部的 viewport-fixed 遮罩和右侧面板，不挂在表格或局部容器内。
- 遮罩点击、拖动、滑动不得关闭面板。只允许固定右上角关闭按钮、面板内明确动作及允许状态下的 `Escape` 关闭。
- 面板外框 `overflow: hidden`；标题区和关闭按钮固定，只有分组内容区 `overflow-y: auto`。
- 打开动画为遮罩淡入、面板从右向左进入，`200ms ease-out`；关闭反向执行，`150ms ease-in`，动画完成后卸载。
- `prefers-reduced-motion: reduce` 时取消位移，仅保留不超过 `50ms` 的淡入淡出或无动画。
- 打开后聚焦面板标题；Tab 和 Shift+Tab 保持在顶层面板内。关闭动画结束后焦点返回对应用户行的「操作」按钮。
- 背景页面及下层界面必须对指针、键盘和辅助技术不可用，并锁定页面滚动。
- 使用 `role="dialog"`、`aria-modal="true"` 和由可见标题关联的 `aria-labelledby`。
- 关闭按钮固定在右上角，`aria-label="关闭"`，触控目标至少 44×44 CSS px。
- 面板宽度使用响应式约束；窄屏接近全宽，并适配动态视口和左右／上下安全区。
- 关闭、路由切换或卸载后清除滚动锁、`inert`、焦点陷阱、监听器、动画及临时提示状态；重新打开不得残留上一用户状态。

## 错误和边界状态

- 未选择用户时不得打开操作面板。
- 用户数据刷新或目标用户消失时，安全关闭面板并把焦点移到用户表格或搜索框。
- 现有动作提交失败时沿用对应 Dialog 的错误呈现，不关闭操作面板或误报成功。
- 异步动作期间阻止重复提交和重复关闭；若业务明确不允许中断，应同时禁用关闭按钮和 Escape，并说明原因。
- 权限数据尚未接入前不伪造细粒度权限；所有入口以现有管理员可见范围展示。后续接入权限时由同一配置控制可见或不可用状态。

## 组件边界

- 用户列表页：管理当前用户、快捷菜单和目标流程编排，不直接维护全部入口的展示细节。
- 用户操作入口配置：维护入口名称、分组、状态、风险和处理器映射，作为快捷菜单与操作面板的单一来源。
- 用户操作面板：只负责分组呈现、焦点／Drawer 生命周期和入口事件派发。
- 现有用户操作组件：继续负责具体表单、校验、MFA 和提交，不复制业务逻辑。

## 验收与验证

实现后至少验证：

- 快捷菜单内容、顺序、行点击隔离以及键盘操作。
- 四个分组、全部入口名称、已有／待接入状态和危险动作位置。
- 已有入口能正确复用现有功能，待接入入口不会改变数据。
- Drawer 遮罩点击、拖动和滑动均不关闭；关闭按钮与 Escape 行为正确。
- 打开／关闭动画时序、动画结束后卸载、重复操作防护和减少动态效果。
- 焦点进入、Tab 循环、顶层隔离、关闭后焦点恢复以及层叠 Dialog 返回焦点。
- 页面滚动锁、内容区独立滚动、固定标题／关闭按钮和清理逻辑。
- 桌面宽屏、移动窄屏、低高度视口、200% 缩放、动态视口与安全区。
- 现有用户详情、入金、调账、划转、封户、点控及日志流程不回归。

没有实际执行的交互或视口检查必须在交付说明中标为未验证，并列出所需检查。

## 后续业务实现顺序

入口完成后按以下顺序拆分功能实现：

1. 用户关系与团队查看
2. 资金冻结、解冻、划扣和流水限制
3. 信用分与会员等级
4. 返利、累计充值、后台记录和地址管理

每批功能单独明确权限、审计日志、MFA、失败恢复和业务状态规则，不在入口阶段提前假设。
