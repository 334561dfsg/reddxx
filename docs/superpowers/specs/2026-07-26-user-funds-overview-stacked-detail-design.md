# 用户资金概况叠层打开设计

## 目标

在 `/admin/users/list` 的“更多操作 → 资金概况”中，直接打开现有用户详情抽屉的“资产”页签，同时保留下层“用户操作”抽屉。关闭用户详情后，用户返回原来的操作上下文。

## 当前问题

当前处理器把 `detail` 和 `assets` 操作保存为延迟动作，先关闭用户操作抽屉，等关闭动画结束后再打开用户详情。这会中断操作上下文，也与同一操作抽屉内其他子功能的叠层模式不一致。

## 方案

- `assets` 操作直接调用现有 `openUserDetail(user, 'assets', trigger)`。
- 不调用 `closeOperationDrawer()`，不写入 `deferredDrawerAction`。
- 用户详情抽屉作为新的最上层模态层，用户操作抽屉保留在下层并保持背景隔离。
- 用户详情关闭动画完成后，焦点返回触发此次操作的“资金概况”按钮。
- 列表行快捷“资金”按钮继续直接打开用户详情的资产页签，既有行为不变。
- `detail` 操作不在本次范围内，保持现有行为，避免扩大变更语义。

## 数据与错误

复用现有 `UserDetailDrawer`、当前用户对象和资产页签，不新增请求、数据仓库或错误状态。若用户详情本身无法渲染，继续使用其既有空值与关闭行为。

## 交互约束

- 同时只允许用户详情抽屉作为最上层交互层；下层用户操作抽屉与页面保持不可交互。
- 遮罩点击不得关闭任一抽屉。
- 关闭用户详情后只恢复到“资金概况”按钮一次，不关闭下层用户操作抽屉。
- 两个抽屉继续使用共享层级、滚动锁、焦点陷阱、动画与清理机制。
- 本次不修改响应式布局、动画、关闭按钮、滚动区域或业务能力。

## 测试

- 先修改编排测试，断言 `assets` 分支直接调用 `openUserDetail(user, 'assets', trigger)`。
- 断言该分支不调用 `closeOperationDrawer()`，也不设置延迟动作。
- 保留列表行“详情 / 资金”快捷入口的页签断言。
- 运行用户操作入口、用户详情抽屉、共享 Dialog/Drawer 层级相关测试。

## 验收标准

1. 打开任意用户的“更多操作”，点击“资金概况”。
2. 用户详情抽屉直接在上层打开，并选中“资产”页签。
3. 下层用户操作抽屉不关闭、不闪烁、不丢失滚动和上下文。
4. 关闭用户详情后，焦点回到下层“资金概况”按钮，用户可继续执行其他操作。
