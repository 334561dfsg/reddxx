# 用户链上钱包演示数据设计

## 目标

在 `/admin/users/list` 的“更多操作 → 链上钱包”中，为 `user_chen（user_1004）` 提供可直接演示的多币种、多网络地址数据，同时保留现有只读、脱敏、查看和复制行为。

## 范围

- 将 `user_1004` 的链上钱包数据从 2 条扩充为 8 条。
- 入金地址与提现地址各 4 条。
- 两类地址均覆盖 USDT-TRC20、USDT-ERC20、BTC 和 ETH。
- 数据包含启用与停用状态、稳定 ID、标签以及首次/最后使用时间。
- 将仓库状态值 `inactive` 显示为中文“停用”。
- 不新增地址编辑、删除、白名单、归集、MFA 或请求流程。
- 不为其他用户生成兜底演示数据；未知用户继续返回空地址列表。

## 数据设计

每条记录保持现有字段契约：`id`、`userId`、`kind`、`coin`、`network`、`address`、`label`、`status`、`firstUsedAt`、`lastUsedAt`。

入金地址：

1. USDT / TRC20，启用，主入金地址。
2. USDT / ERC20，启用，以太坊 USDT 入金地址。
3. BTC / Bitcoin，启用，比特币入金地址。
4. ETH / Ethereum，停用，历史 ETH 入金地址。

提现地址：

1. USDT / TRC20，启用，常用提现地址。
2. USDT / ERC20，停用，历史 ERC20 提现地址。
3. BTC / Bitcoin，启用，BTC 冷钱包。
4. ETH / Ethereum，启用，ETH 常用钱包。

地址使用与网络相符的稳定演示格式，不使用真实私钥或凭据。所有 ID 和时间固定，刷新与测试结果可重复。

## 数据流与安全

`getUserOnchainWallet(userId)` 继续返回深拷贝，组件修改展示数据不能污染仓库。地址默认仍脱敏；只有用户主动点击“查看完整地址”后才能复制。停用仅表示该地址当前不可作为业务默认地址，不改变本只读演示抽屉中的查看和复制能力。

## 交互

抽屉继续在用户操作抽屉之上打开，下层保持挂载。入金/提现分组、固定标题、内容区滚动、遮罩阻断、焦点返回、关闭动画和安全区域行为均保持不变。状态徽标增加明确映射：`active → 启用`、`inactive → 停用`，未知状态继续显示原状态值或“未知”。

## 测试

- 仓库测试先断言总数为 8、入金/提现各 4，并逐组覆盖四种币种/网络组合。
- 断言稳定 ID 唯一、字段完整、状态同时包含 `active` 与 `inactive`。
- 保留未知用户、用户 ID 规范化和深拷贝测试，并将深拷贝长度预期更新为 8。
- 抽屉测试断言停用状态显示为“停用”，同时保留脱敏、查看、复制、分组和 Drawer 生命周期测试。

## 验收标准

1. 打开 `user_chen` 的“更多操作 → 链上钱包”。
2. “入金地址”展示 4 条，“提现地址”展示 4 条。
3. 两个分组都能看到 USDT-TRC20、USDT-ERC20、BTC 和 ETH。
4. 启用与停用徽标均使用中文且不只依赖颜色表达。
5. 每条地址默认脱敏，可独立查看完整地址并复制。
6. 关闭链上钱包后仍返回下层原操作卡片。
