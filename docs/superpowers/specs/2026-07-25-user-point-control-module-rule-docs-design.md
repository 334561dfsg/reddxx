# 用户点控模块规则文档设计

## 1. 目标

为交割、永续、现货、AI量化、流动性挖矿、投资组合分别编写一份可独立复制到对应模块产品文档中的规则说明。文档主要供开发和测试使用，应能指导功能开发，并可直接据此拆分测试用例。

## 2. 交付形式

- 输出 6 份独立 Markdown 文档，每个模块一份。
- 每份文档控制在约 1 页，避免重复产品背景、名词解释和技术实现说明。
- 文档只描述产品规则，不包含接口、数据库、事务或结算服务实现方案。
- 每份文档可以脱离其他五份文档单独阅读和使用。

## 3. 每份文档结构

每个模块只保留以下五部分：

1. **操作**：入口、设置项、修改和取消范围。
2. **触发**：生效事件以及明确不触发的事件。
3. **规则**：控制结果、金额计算责任、一次性与永久规则、优先级。
4. **状态**：设置、成功执行、失败、覆盖、取消后的状态变化。
5. **验收点**：5～8 条可直接转换为测试用例的预期结果。

## 4. 六模块口径

| 模块 | 控制内容 | 有效触发事件 |
| --- | --- | --- |
| 交割 | 盈利／亏损 | 交割合约到期并完成最终结算 |
| 永续 | 盈利／亏损 | 目标持仓最终平仓并完成结算 |
| 现货 | 盈利／亏损 | 卖出完成、原始净盈亏确定并进行最终结算 |
| AI量化 | 高收益／低收益 | 产品结算或实际收益成功入账 |
| 流动性挖矿 | 高收益／低收益 | 周期结算、收益领取或赎回结算成功入账 |
| 投资组合 | 高收益／低收益 | 到期结算、赎回结算或实际收益成功入账 |

交易模块只约束扣除相关费用后的最终已实现盈亏方向，不修改公共行情。现货保留真实成交形成的原始净盈亏，通过独立损益调整形成最终方向，不修改成交数据。理财模块只选择产品允许范围内的收益档位，不直接指定收益率或收益金额，也不得突破产品自身收益边界。

## 5. 通用规则

- 管理员只设置控制方向和生效方式，不填写具体金额、价格或收益率。
- 模块点控只影响当前模块；用户点控设置会覆盖六个模块的当前规则。
- 一次性规则设置后为“待执行”，仅在一次有效事件成功完成后变为“已执行”。失败事件不消费规则，仍为“待执行”。
- 永久规则设置后为“生效中”，每次有效事件均可生效，直到被取消或覆盖。
- 修改规则时旧规则变为“已覆盖”；取消后变为“已取消”。
- 优先级为：单笔订单或持仓控制 > 当前模块用户点控 > 用户管理用户点控 > 模块全局场控 > 自然结果。
- 所有设置、修改、覆盖、取消、执行成功和执行失败均应保留日志。

## 6. 不纳入文档的内容

- 前端 Demo 或 Mock 实现方式。
- API、数据库字段和服务端事务设计。
- 具体金额、收益率或价格的生成算法。
- 权限系统和 MFA 的技术实现。
- 与当前模块点控无关的完整用户点控产品背景。

## 7. 完成标准

- 六份文档结构一致、篇幅精简且可独立复制。
- 每份文档明确控制对象、触发与不触发条件、状态变化和优先级。
- 交易模块明确按费用后的已实现净结果判断，且不修改公共行情。
- 理财模块明确收益档位受产品边界约束。
- 一次性规则失败不消费、永久规则持续生效等通用规则在每份文档中均无歧义。
- 每份文档的验收点可直接被测试人员转换为测试用例。
