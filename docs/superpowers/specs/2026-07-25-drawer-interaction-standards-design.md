# 抽屉交互规范设计

## 目标

在 `frontend-product-interaction-standards` Skill 中新增独立、可自动触发的抽屉交互规范，覆盖从上、下、左、右四个方向进入的 Drawer、Sheet 和抽屉式面板，并将关键约束同步到 `fex-admin/AGENTS.md`。本次只更新规范，不修改现有业务组件。

## 组织方式

- 新增 `references/drawers.md`，作为抽屉规则、验收标准和参考资料的唯一事实来源。
- 在 `SKILL.md` 增加路由：涉及 Drawer、Sheet、抽屉或侧滑/上下滑出面板时，必须完整读取 `references/drawers.md`。
- 在公开 `README.md` 增加抽屉能力摘要和目录项。
- 在项目 `AGENTS.md` 增加精简但完整的抽屉硬性约束，确保其他 Agent 即使未加载 Skill 也能执行关键规则。

## 统一交互规则

1. 所有模态抽屉使用覆盖完整浏览器视口的遮罩，并挂载到不会受局部容器、定位上下文或 `transform` 裁切的位置。
2. 点击遮罩不得关闭抽屉或触发关闭动画；不得通过拖拽、滑动或拖拽条关闭。抽屉只能通过内部关闭按钮、取消、确认或明确业务操作关闭。
3. 允许用户退出的普通抽屉必须在固定标题区域右上角提供始终可见、可聚焦且具有 `aria-label="关闭"` 的关闭按钮。底部操作不能替代该按钮。只有业务明确规定不可中断、强制确认或安全流程禁止退出时才可隐藏或禁用，并必须表达原因。
4. 抽屉外框保持不可滚动；限制抽屉尺寸，仅内容区域滚动。标题、右上角关闭按钮、底部操作和必要状态区域不得随内容滚出视口。
5. 打开期间隔离页面背景并锁定页面滚动；关闭动画完成后才卸载，并恢复焦点、滚动、`inert`、监听器和临时状态。

## 方向与布局

- 左抽屉固定于视口左边缘，从左向右进入、向左退出；右抽屉行为镜像。
- 上抽屉固定于视口顶部，从上向下进入、向上退出；下抽屉行为镜像。
- 左右抽屉限制宽度并使用视口可用高度；上下抽屉限制高度并使用视口可用宽度。
- 尺寸必须适配移动端、缩放、低高度视口、动态视口和虚拟键盘，不依赖会导致内容或操作不可达的固定像素高度。
- 顶部和底部抽屉处理 `safe-area-inset-top` / `safe-area-inset-bottom`；左右抽屉处理对应横向安全区域。

## 动画

- 遮罩打开时淡入，抽屉从其所属边缘外沿平移到最终位置，使用 `200ms ease-out`。
- 关闭时反向平移并淡出，使用 `150ms ease-in`；完成前保留遮罩、焦点约束和滚动锁定。
- 动画期间屏蔽重复打开、关闭与回调。
- `prefers-reduced-motion: reduce` 下取消位移动画，淡入淡出不超过 `50ms`，或直接切换。

## 焦点、键盘与语义

- 打开后将焦点移到标题、首个合理操作或风险最低的操作；`Tab` 与 `Shift + Tab` 仅在最上层抽屉内循环。
- `Escape` 默认只关闭最上层抽屉；不可中断、提交中或有未保存内容时禁用或先确认。
- 关闭动画完成后将焦点返回触发元素；触发元素不存在时选择合理的后续目标。
- 模态抽屉使用原生模态能力，或 `role="dialog"`、`aria-modal="true"` 和可访问名称；非模态抽屉不得错误声明 `aria-modal="true"`，且不得无故隔离背景。
- 多层抽屉或抽屉与 Dialog 叠加时，只有最上层可交互，并使用统一层级体系和焦点返回链。

## 异步、错误与状态清理

- 异步操作期间防止重复提交、重复关闭和重复回调；加载控件保留可访问名称和状态。
- 失败后保持抽屉打开，提供可读错误并将焦点引导到合理位置。
- 关闭、路由变化、组件卸载和重新打开时，清理或重置滚动锁定、背景隔离、焦点陷阱、监听器、动画、loading 和错误状态。

## 验收

- 分别验证上、下、左、右四种抽屉的进入和退出方向、时长及 Reduced Motion。
- 点击遮罩并执行拖拽/滑动，确认抽屉保持打开；再验证内部关闭按钮、取消、确认与 Escape 的允许和禁止场景。
- 使用长内容确认只有内容区域滚动，固定标题、右上角关闭按钮和底部操作始终可见。
- 验证全视口遮罩、页面滚动锁定、背景隔离、焦点进入/循环/返回、多层叠加和资源清理。
- 在桌面、移动端、缩放、低高度、动态视口、虚拟键盘和安全区域设备上验证内容及操作均可访问。
- 未实际执行的交互或视口检查必须明确报告为未验证，并列出所需检查。

## 范围边界

- 本次不修改现有抽屉组件或页面。
- 本次不把普通非模态侧栏、固定导航栏或无覆盖关系的页面分栏强制视为模态抽屉。
- 后续业务代码整改由其他 Agent 按更新后的 Skill 和项目约束独立执行。
