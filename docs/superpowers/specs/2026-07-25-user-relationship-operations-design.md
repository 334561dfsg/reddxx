# 用户关系操作与多层界面设计

## 目标与范围

本阶段实现用户操作中心第一批「用户与关系」功能，并修复操作中心 Drawer 打开子 Dialog 或子 Drawer 时的遮挡、焦点和背景隔离问题。

本阶段包含：

- 编辑资料
- 查看直属下级
- 查看全部下级
- 重设上级
- 设置／重设代理
- 查看团队报表
- 将现有入金、调账、账户划转、封户／解封、统一点控、取消点控等子界面纳入统一层级体系

本阶段使用当前前端模拟用户数据作为功能数据源。所有数据变更都通过独立的用户关系仓储执行，页面和弹窗不得直接散落修改 `usersList`。

## 方案选择

采用「父操作 Drawer 保持挂载，子界面注册为更高层」的共享层级方案。

不采用先关闭父 Drawer 再打开所有子功能：这种方式虽然不会遮挡，但子功能关闭后无法返回原操作位置，会打断同一用户的连续操作。

不采用单独增大旧组件 `z-index`：它只能处理视觉覆盖，不能保证最上层 Escape、焦点陷阱、背景 `inert`、滚动锁和关闭后的焦点返回。

## 统一层级模型

共享 Dialog 生命周期是层级的唯一事实来源。所有模态 Drawer、Dialog 和确认层在渲染后注册，按注册顺序获得层级，不允许业务组件继续使用固定的模态 `z-index`。

层级语义如下：

1. 用户操作中心 Drawer 为第一层。
2. 关系查看 Drawer、团队报表 Drawer、编辑或重设 Dialog 为第二层。
3. 危险操作确认或 MFA 为第三层。

任何时刻只有最上层可交互。下层界面和页面背景保持 `inert`，但下层 DOM、表单状态和滚动位置仍保留。Escape 一次只关闭最上层；关闭子层动画完成后，焦点返回父 Drawer 中触发该功能的操作卡片。

用户详情和点控日志属于同级目标流程，不叠加在操作中心上：先完成操作中心的 150ms 关闭动画，再打开目标 Drawer 或切换路由。

现有入金、调账、账户划转、封户／解封、统一点控和取消点控属于子任务，直接叠加在操作中心之上。它们迁移到共享层级后，由生命周期生成层级样式，并遵守相同的焦点、Escape、滚动锁和背景隔离规则。

## 数据与领域边界

新增用户关系仓储，封装以下查询和变更：

- 按用户 ID 获取用户。
- 获取直属下级。
- 获取全部后代，并返回层级、直属上级和关系路径。
- 判断候选上级是否会形成自己指向自己或指向后代的闭环。
- 更新用户基础资料。
- 重设用户上级，同时同步 `parentId` 和 `parentUsername`。
- 设置、重设或取消代理身份。
- 汇总团队报表。

用户标识统一使用现有 `id` 字段；展示时兼容 `userId`。关系路径计算必须使用访问集合，遇到脏数据循环时停止遍历并返回可识别的异常状态，不能造成无限递归。

敏感变更产生本地审计记录，至少包含操作类型、目标用户、变更前值、变更后值、原因和时间。审计记录仅表示前端模拟操作，不伪造后端请求成功。

## 编辑资料

「编辑资料」打开第二层 Dialog，标题明确为「编辑用户资料」，展示用户名和 UID。

可编辑字段：

- 用户名：必填，去除首尾空格，同其他用户不重复。
- 邮箱：必填，使用基础邮箱格式校验，同其他用户不重复。
- 手机号：可空；填写时必须为可接受的国际号码文本，同其他用户不重复。
- 备注：可空，最多 200 字。

打开时建立表单快照；取消或关闭不保存。提交期间禁用重复提交和关闭路径。失败时保持 Dialog 打开并聚焦错误摘要；成功后更新用户列表和当前操作中心显示的用户快照，再关闭子层并返回「编辑资料」卡片。

## 查看直属下级与全部下级

两个入口复用 `UserRelationshipDrawer`，通过 `mode="direct"` 或 `mode="all"` 区分数据范围。

Drawer 固定标题和工具区，正文独立滚动。工具区提供：

- 用户名、邮箱或 UID 搜索。
- 账户状态筛选。
- 角色筛选。

直属模式只展示 `parentId` 等于目标用户 ID 的成员。全部模式按广度优先顺序展示所有后代，并显示：

- 所在层级。
- 直属上级。
- 完整关系路径。
- 用户状态、角色、余额和注册时间。

列表为空时区分「当前没有下级」和「筛选后没有结果」。点击成员只更新关系 Drawer 内的选中摘要，不再打开第三个用户详情 Drawer，避免把浏览动作扩展为不必要的三层导航。

## 重设上级

「重设上级」打开第二层敏感操作 Dialog。

表单包含：

- 当前上级只读信息。
- 新上级可搜索选择器。
- 必填变更原因，最多 200 字。

候选上级排除：

- 当前用户本人。
- 当前用户的任意后代。
- 已是当前上级的用户。
- 状态为封禁的用户。

顶级用户允许选择「设为无上级」。提交前再次从仓储计算闭环校验，不能只信任界面候选列表。确认页展示旧上级、新上级和预计影响的后代数量；确认后原子更新 `parentId` 与 `parentUsername` 并写入审计记录。

## 设置／重设代理

「设置／重设代理」打开第二层敏感操作 Dialog。

普通用户可设置为代理；代理用户可更新代理归属说明或取消代理身份。表单包含目标身份、变更原因和影响摘要。

取消代理时：

- 没有直属下级可直接进入确认。
- 存在直属下级时必须先为这些下级选择统一承接上级，或选择设为无上级。
- 承接上级同样不得是目标用户本人或其后代。

提交确认后统一更新用户角色及受影响成员关系，并写入一条包含影响成员 ID 的审计记录。身份和关系更新作为同一仓储事务执行；任一校验失败都不写入部分结果。

## 团队报表

「查看团队报表」打开第二层只读 Drawer。汇总范围为目标用户的全部后代，不包含目标用户本人。

概览指标：

- 团队总人数。
- 直属人数。
- 代理人数。
- 活跃人数。
- 总可用余额。
- 总冻结余额。
- 总交易量。
- 团队累计盈亏。

明细按第一层分支汇总，展示每个直属成员所代表分支的人数、资产、交易量和盈亏。所有数值由当前成员数据实时派生，避免另存一份容易过期的统计状态。没有团队成员时展示空状态，不用零值卡片填满页面。

## 操作中心编排

入口配置中上述六项由 `planned` 改为 `available`，分别映射到明确处理器。操作中心发出动作时记录当前卡片元素，作为子层关闭后的返回焦点。

父 Drawer 不直接持有六个业务表单；用户列表页只负责编排当前用户、当前子功能和层间打开／关闭。每个功能组件负责自己的表单、校验、错误和生命周期。

为了避免用户列表页继续膨胀，关系查询和变更放入仓储，关系展示放入一个复用 Drawer，编辑、重设上级和代理变更使用各自职责单一的 Dialog，团队报表使用独立 Drawer。

## Dialog 与 Drawer 交互要求

所有新增及迁移界面必须满足项目交互规范：

- 遮罩点击、拖动和滑动不关闭，也不启动关闭动画。
- 固定视口遮罩挂载到 `body`；面板外框 `overflow: hidden`，仅正文区域纵向滚动。
- 标题区右上角保留始终可见、可聚焦且 `aria-label="关闭"` 的关闭按钮。
- 打开采用 200ms `ease-out`，关闭采用 150ms `ease-in`，关闭动画完成后卸载。
- 减少动态效果时取消缩放或位移，淡入淡出不超过 50ms。
- 打开后聚焦合理目标，Tab 和 Shift+Tab 只在最上层循环。
- 使用 `role="dialog"`、`aria-modal="true"` 和可见标题关联的 `aria-labelledby`。
- 提交中阻止重复提交；若提交可中断则保留安全关闭，若不可中断则禁用所有关闭路径并说明原因。
- 错误保持界面打开，提供文本错误并将焦点移到错误摘要。
- 桌面、窄屏、低高度、动态视口和安全区域下，标题、关闭按钮及操作始终可达。
- 关闭、路由切换和卸载时清理层级、`inert`、滚动锁、焦点陷阱、监听器和临时状态。

## 测试与验收

领域测试覆盖：

- 直属与全部后代查询、层级和路径。
- 无下级、深层关系和异常循环数据。
- 重设上级的本人、后代、当前上级和封禁候选排除。
- 编辑资料唯一性与格式校验。
- 代理设置、取消代理和直属成员重挂载的原子性。
- 团队统计及分支统计。

组件与页面测试覆盖：

- 六个入口状态和处理器映射。
- 父 Drawer 与子层同时挂载时，子层位于最上层且父层 `inert`。
- Escape 一次只关闭一层，关闭子层后焦点回到原卡片。
- 遮罩点击、固定标题、正文滚动、动画时序和减少动态效果。
- 编辑、重设上级和代理变更的校验、重复提交及错误状态。
- 现有入金、调账、划转、封户和点控界面从操作中心打开时不再被遮挡。

浏览器实测覆盖桌面和窄屏下的六个入口、长列表滚动、父子层切换、遮罩抵抗、焦点返回和现有操作层级。200% 缩放、低高度、减少动态效果、虚拟键盘和安全区域未实际验证时，交付说明必须明确列出。

## 后续批次

完成本阶段后依次推进：

1. 资金冻结、解冻、划扣和出金流水限制。
2. 信用分审核、信用分调整和会员等级。
3. 返利奖励、会员累计充值、后台划扣记录、链上钱包和手动上分地址。

每一批继续复用本设计的层级系统、仓储边界、审计结构和交互验收规则。
