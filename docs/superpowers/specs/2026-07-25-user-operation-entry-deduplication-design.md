# 用户操作入口去重设计

## 背景与目标

用户操作抽屉当前同时存在按业务对象命名的入口和按历史组件命名的入口。最明显的问题是“调账”位于资金分组，但实际修改 VIP 等级和信用分；“详情”和“资金概况”目前又进入同一个默认视图。此次调整只整理入口的信息架构和落点，不改变已经确认的资金控制业务规则。

目标是让管理员能够仅凭入口名称判断资产是否会增加、减少或只在账户之间移动，并减少抽屉中的一级入口数量。

## 最终入口结构

### 用户与关系

保持现状：编辑资料、查看直属下级、查看全部下级、重设上级、设置／重设代理、查看团队报表。

### 资金与钱包

保留以下一级入口：

1. 资金概况
2. 链上钱包
3. 客服入金
4. 账户间划转
5. 冻结全部资金
6. 解冻后台冻结
7. 划扣可用资金
8. 出金流水限制

移除“调账”“后台划扣记录”“手动上分地址”三个一级入口：

- “调账”现有能力拆回信用与会员分组，不再以资金操作出现。
- “后台划扣记录”作为“划扣可用资金”的辅助入口，并可在资金概况的流水区域查看。
- “手动上分地址”放入“链上钱包”的地址管理区域。

### 信用与会员

保留并分别实现：信用分审核、修改信用分、编辑会员等级、会员累计充值、添加返利奖励。

原“调账”组件中的 VIP 和信用分能力不再作为一个组合提交。管理员每次只执行一种明确操作，以便权限、审核、MFA 和审计记录分别控制。

### 风控与控制

保持现状：封户／解封、统一点控、取消点控、点控日志。

## 入口语义与落点

### 详情与资金概况

- 列表“详情”打开用户详情抽屉的默认资料视图。
- “资金概况”打开同一个详情抽屉，但初始定位到资产区域。
- 两者复用同一组件，但入口意图和首屏内容必须不同。

### 账户间划转

将“账户划转”改名为“账户间划转”。操作只在同一用户的内部账户之间移动资产，用户总资产不变。确认界面必须展示来源账户、目标账户、币种、金额以及划转前后余额。

### 划扣可用资金

划扣会永久减少用户可用资产，不属于划转。入口使用危险操作样式，要求填写原因、二次确认和 MFA。成功后生成不可修改的划扣记录。

### 链上钱包与上分地址

“链上钱包”是一级入口，展示钱包、链、地址和状态。“手动上分地址”作为其中的地址管理动作，不再占用操作抽屉一级位置。

## 弹层与焦点层级

所有从用户操作抽屉打开的交互保持父抽屉挂载：

1. 用户操作抽屉为第一层。
2. 业务 Dialog 或子 Drawer 为第二层。
3. MFA 或不可逆操作确认 Dialog 为第三层。

每一层通过共享 `useDialogLifecycle` 注册动态层级；仅最上层可交互，下面的抽屉和页面保持 `inert`。子层关闭后焦点返回原操作卡片。不得通过关闭父抽屉来规避遮挡，也不得使用局部固定 `z-index`。

遮罩、拖动和滑动不得关闭 Dialog 或 Drawer。框架保持不可滚动，只有内容区域滚动；固定头部保留可见且可聚焦的关闭按钮。

## 数据与兼容策略

- 操作目录只负责入口名称、分组、风险和处理器映射。
- 现有 `UserTransferAction` 继续作为账户间划转的实现基础。
- 现有 `UserAdjustAction` 不再从操作目录暴露；其 VIP 与信用分逻辑在对应独立功能实现后删除或拆分，避免双路径写入。
- “资金概况”的目标区域通过显式初始视图参数传递，而不是依赖 DOM 查询或定时滚动。
- 已有直接链接或内部调用若仍使用 `adjust`，在迁移期间保留兼容映射，但不得继续显示“调账”一级入口。

## 错误与安全处理

- 无效金额、余额不足、相同来源和目标账户、缺少原因等错误在当前弹层中以文本展示并聚焦错误摘要。
- 异步提交期间禁止重复提交、关闭和回调。
- 失败不得自动关闭；成功后仅关闭当前业务层，父操作抽屉仍保持可用。
- 危险资金操作必须记录操作人、用户、时间、原因、操作前后值和流水号。

## 测试与验收

1. 操作目录不再显示“调账”“后台划扣记录”“手动上分地址”。
2. 资金分组显示最终八个一级入口，且“账户间划转”和“划扣可用资金”描述明确区分总资产是否变化。
3. “详情”进入默认视图，“资金概况”直接进入资产视图。
4. VIP 和信用分不再通过一个组合入口提交。
5. 从父操作抽屉打开账户间划转或后续资金操作时，子层位于父层上方，父层保持挂载且不可交互。
6. 子层关闭后焦点返回原卡片；遮罩点击不关闭，Escape 只关闭最上层。
7. 桌面、窄屏和低高度视口下只有内容区滚动，关闭按钮和必要动作保持可达。
8. 现有用户关系、风控、入金和详情功能回归测试继续通过。

## 实施边界

本次入口整理先完成目录、命名、落点和兼容迁移。“冻结全部资金、解冻后台冻结、划扣可用资金、出金流水限制、链上钱包、信用与会员”等尚未实现的业务能力，继续按后续独立批次逐项设计和实现；入口整理不以占位提示冒充功能完成。
