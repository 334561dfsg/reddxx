# 用户链上钱包与选择控件规范化设计

## 目标

完成用户“更多操作”中最后一个待实现入口“链上钱包”，并把该操作体系内仍使用旧式原生 `<select>` 的选择场景按最新 Select / Combobox 规范分类处理。所有新增或改造的弹层继续使用共享层级系统，不能被父“更多操作”抽屉遮挡。

## 链上钱包入口

“链上钱包”是只读的右侧 Drawer，直接叠加在“更多操作”抽屉之上，父抽屉保持挂载。Drawer 展示当前用户的充值地址和常用出金地址，字段包括币种、网络、完整地址、地址标签、状态、首次使用和最后使用时间。

地址默认脱敏，用户可通过单条记录内的“查看完整地址”显式展示，再执行复制。关闭 Drawer 后焦点返回原“链上钱包”操作卡片。该入口不提供新增、修改、删除、归集或白名单变更，避免与资产管理和公共收款地址配置重复，因此不需要 MFA。

地址类型只有“充值地址”和“常用出金地址”两个稳定选项，使用可见分段按钮，不使用 Select。币种与网络仅作为记录内容展示；当前数据量不需要搜索或筛选控件。

## 数据边界

新增只读用户链上钱包仓储，按 `userId` 返回稳定、可重复的模拟数据。返回值必须深拷贝，调用方不能修改仓储状态。每条地址包含稳定 ID，并以 `kind` 区分 `deposit` 和 `withdrawal`。

Drawer 不从 `UserDetailDrawer` 的组件内部抓取数据；两者使用相同的业务口径，但链上钱包拥有独立仓储接口，避免 UI 组件之间形成隐式依赖。

## Select / Combobox 现状分类

本次审计范围是用户操作入口及其直接打开的组件。

### 改为可见选择

- 客服入金的目标账户：选项少且稳定，使用原生 radio card。
- 账户间划转的转出账户、转入账户和币种：选项少且稳定，使用带可见标签的 radio card；禁用同一转入账户，不能静默改值。
- 用户关系 Drawer 的状态和角色筛选：选项少且属于过滤条件，使用可换行的分段按钮；当前值始终可见。
- 旧版信用/VIP 调整组件中的 VIP 等级：与新会员操作保持一致，使用可见 radio card。

这些场景不构造 `searchPlacement="none"` 的自绘 Combobox，因为直接展示全部选项更少点击、更容易扫描，且不需要折叠以节省空间。

### 使用最新可搜索 Combobox

- 重设上级的候选用户。
- 取消代理身份时的承接上级候选用户。
- 旧版信用分行为规则选择；规则数量可能扩展，并需要按名称查找。

用户候选属于高频按用户名或 UID 搜索，显式采用 `panel`：外层 disclosure 显示已提交值，打开后内层搜索 Combobox 只维护查询草稿，点击可用 option 或对 active option 按 Enter 才提交。“重设上级”原有的独立“搜索新上级”输入框删除，邮箱仍合并进 Combobox 的 `searchText`，避免同一字段出现两个搜索入口。规则选择同样使用 `panel`，避免在 Dialog 内再增加一个全屏 Drawer 层。

统一组件必须维护 committed value、query、active option 与会话快照；非提交关闭恢复 committed value。Listbox/option 使用稳定 ID，唯一 active option 设置 `aria-selected="true"`，键盘、错误、disabled/orphaned invalid 和动画遵循最新版规范。

### 暂不改造的范围

`UserDetailDrawer` 内嵌的旧入金/划转表单不是当前“更多操作”入口的执行路径，且与独立 `UserDepositAction` / `UserTransferAction` 重复。本批先保持只读详情和现有兼容行为，不在同一变更中重构整个详情 Drawer。完成后另行审计是否应删除这些重复表单，而不是复制一套新选择器进去。

## 层级与交互

链路为：页面 → 更多操作 Drawer → 链上钱包 Drawer。两层都通过 `useDialogLifecycle` 注册动态层级；只有顶层可交互。遮罩点击、拖拽和滑动不关闭。Drawer 外框不滚动，只有内容区滚动；标题和右上角关闭按钮固定。打开 200ms ease-out，关闭 150ms ease-in，减少动态效果时不平移且最多 50ms。

可搜索选择器的 panel 通过 Portal 或不受 overflow 裁切的根层显示，但它是非模态 popup，不增加全屏遮罩。Dialog/Drawer 的焦点陷阱仍包含该 popup 的交互节点。

## 错误与边界状态

- 无地址时分别展示对应类型的空状态。
- 剪贴板不可用或复制失败时，地址保持展示并给出文本错误，不伪报成功。
- 地址展示状态和复制错误在 Drawer 每次打开时重置。
- 用户候选或规则已提交值若刷新后失效，保留旧值与标签并标记失效，要求重新选择，不自动清空或替换。
- 所有表单选择改造保持原有提交 payload，不改变仓储业务语义。

## 验证

- 仓储测试：按用户返回、类型分类、稳定 ID、深拷贝与空数据。
- Drawer 真实挂载测试：父层之上打开、遮罩不关闭、显隐、复制失败、内部关闭、动画后焦点返回、单一滚动区。
- 选择器测试：提交值与查询草稿分离、非提交恢复、键盘导航/提交、ARIA 唯一 active、disabled 和 orphaned invalid。
- 各业务组件集成测试：原有 payload 不变，原生 `<select>` 从本次范围内移除。
- 全量测试、生产构建与 `git diff --check`。
- 浏览器手动验证桌面、窄屏、低高度、缩放、触摸、虚拟键盘、多层焦点与 reduced motion；未实际执行的项目必须明确报告为未验证。
