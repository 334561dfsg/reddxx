# PC 与移动端兼容交互规范设计

## 目标

在 `frontend-product-interaction-standards` Skill 中新增跨桌面、平板和移动端的全局响应式与自适应交互规范。规范以“核心业务能力一致；低频、次要能力可以折叠、收纳或转换形态，但不得彻底删除，并且必须保持可发现、可访问”为首要原则。

本次只建立规范，不修改现有页面或组件。后续业务整改由其他 Agent 按新规范执行。

## 组织方式

- 新增 `references/responsive-adaptive.md`，作为 PC、移动端、平板、横竖屏、触摸和断点适配规则的唯一事实来源。
- 在 `SKILL.md` 增加自动路由：涉及响应式、移动端、PC、桌面端、平板、断点、横竖屏、触摸、虚拟键盘或跨端适配时，必须完整读取该文件。
- 在公开 `README.md` 增加跨端能力摘要和目录项。
- 在项目 `AGENTS.md` 增加可独立执行的关键硬性约束。
- `dialogs.md`、`drawers.md` 等组件规范保留自己的跨端细节；全局规范与组件规范同时适用，冲突时执行更严格规则。

## 核心能力与信息层级

1. PC 与移动端必须提供相同的核心业务能力、数据结果、权限判断、校验、错误处理、安全确认和状态反馈。
2. 不得以屏幕空间不足为由删除关键内容或操作。
3. 低频、次要能力可以折叠到“更多”、Accordion、操作菜单、二级页面、Drawer 或其他合适容器，但必须有清晰入口、可被键盘和辅助技术访问，并能在合理步骤内找到。
4. 组件可以跨端改变布局和交互形态，但不得改变业务语义、提交结果、默认值或风险等级。
5. 不得仅用 `display: none` 隐藏仍需用户访问的能力。

## 适配依据

- 适配应基于可用空间、内容需求、输入能力和用户偏好，不只依赖设备名称或 User-Agent。
- 不假设桌面设备只有鼠标，也不假设移动设备只有触摸；同一界面应支持键盘、鼠标、触摸和辅助技术的合理组合。
- 断点由内容何时无法保持可用来决定，不能机械绑定某个具体设备型号。
- 除宽度外，还必须考虑视口高度、浏览器缩放、系统字体放大、横竖屏、动态浏览器工具栏、虚拟键盘和安全区域。

## 跨端组件转换

- 内容较多的桌面 Dialog 可以在窄屏转换为底部或全屏 Drawer，但必须保留标题、关闭操作、焦点、遮罩、滚动、提交和错误语义。
- 桌面侧边 Drawer 可以在窄屏变为全宽侧边 Drawer 或底部 Drawer，方向改变时仍遵循 Drawer 动画和生命周期规则。
- Hover Tooltip、Popover 和菜单必须提供点击与键盘访问路径；重要信息不得仅依赖 Hover。
- 大型 Select、Combobox 或选项列表可以在移动端转换为底部 Drawer，但选择值、草稿、搜索、错误和焦点返回必须保持一致。
- 宽表格可转换为卡片列表、优先级列、详情展开或受控横向滚动；字段和操作不得无入口地消失。
- 桌面左侧导航可转换为移动端导航 Drawer；当前页面、展开状态、焦点返回和背景滚动必须正确处理。
- 并排表单可改为单列，但字段顺序、关联关系、帮助文本和错误归属必须保持清晰。
- 拖拽、滑动、长按或精确指针操作必须提供简单点击或键盘替代方式。

## 状态延续与断点切换

- 调整窗口、旋转设备或跨断点切换时，不得丢失未提交表单、筛选条件、搜索词、分页、选中项、展开项、上传进度或业务上下文。
- 已打开的浮层发生形态转换时，只保留一个活动实例；不得产生重复遮罩、重复请求、重复回调、多个焦点陷阱或叠加滚动锁。
- 转换后焦点应位于等价内容或操作；无法保持原目标时，移动到新形态中合理的标题或首个操作。
- 路由、查询参数、浏览器前进后退和返回列表时的状态恢复必须在两端保持一致。
- 正在提交、上传或执行不可中断操作时，形态切换不得中断请求或错误地恢复可操作状态。

## 布局、视口与滚动

- 页面必须支持常见桌面、笔记本、平板、窄屏手机和横屏手机视口，并覆盖低高度场景。
- 浏览器缩放到 200% 时，核心内容和操作仍可访问，不产生必须双向滚动才能完成的关键流程。
- 固定顶部栏、底栏、浮动操作和虚拟键盘不得完全遮挡聚焦元素、错误信息或主操作。
- 使用动态视口单位时提供合理回退，并处理 `safe-area-inset-top`、`right`、`bottom`、`left`。
- 页面只能有清晰、可预期的主滚动关系；嵌套滚动不得让用户无法到达内容或操作。
- 横向滚动只能用于确有必要的数据结构，并应确保关键身份信息和操作仍可定位。

## 输入方式与操作目标

- 所有核心操作必须可通过键盘完成，并具有清晰可见的焦点状态。
- 触摸目标及间距必须满足采用的无障碍基线，不能依赖精确点击。
- Hover 出现的补充内容必须支持键盘 Focus；需要交互的浮层还必须支持指针移动进入且不会意外消失。
- 拖拽操作必须提供非拖拽替代，复杂手势不得作为完成关键任务的唯一方式。
- 设备切换输入方式时，界面不得锁定在仅触摸或仅鼠标状态。

## 内容与国际化

- 标题、金额、状态、错误和主要操作优先展示；次要信息折叠后仍必须可发现。
- 支持长标题、长单词、系统字体放大和翻译文本扩展，不得因截断造成关键含义或操作丢失。
- 重要信息不能仅由图标、位置、颜色或 Hover 表达。
- 折叠和收纳入口使用描述性名称，避免只用没有可访问名称的省略号图标。

## 验收矩阵

至少验证以下维度，并记录未执行项：

- 桌面：`1440×900`、`1280×720`。
- 平板：竖屏和横屏。
- 手机：常见窄屏、低高度和横屏。
- 浏览器缩放：至少 200%。
- 输入方式：键盘、鼠标和触摸。
- 虚拟键盘：关闭与打开。
- 动态视口和四向安全区域。
- Reduced Motion 和高对比度或等价可视性检查。
- 长文本、超长标题、字体放大和国际化文本。
- 断点切换时存在未保存表单、活动筛选、打开浮层、上传或加载请求。

每次修改只需执行与变更相关的矩阵项，但未实际执行的交互、输入方式或视口检查必须明确报告为未验证，并说明所需验证。

## 范围边界

- 本规范定义产品交互与验收，不规定具体 CSS 框架、组件库或工程目录结构。
- 不要求 PC 与移动端像素级一致；要求核心能力、业务语义、安全性和可访问性一致。
- 不禁止合理的跨端形态转换，但禁止以“移动端精简”为由彻底删除仍有业务价值的能力。
- 本次不整改现有业务代码，也不建立具体页面的适配清单。
