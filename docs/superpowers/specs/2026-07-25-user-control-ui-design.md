# 单用户跨模块控制——界面 Demo 设计

## 1. 文档目的

本文定义后台管理界面的演示范围和交互方式。当前项目仅用于界面设计与交互演示，所有数据变化使用现有 Vue `mock/state` 方式模拟，不接入真实接口、行情或结算服务。

业务规则和验收口径见《单用户跨模块控制——业务规则与验收说明》。

## 2. 设计结论

系统提供两类入口：

1. 用户管理中的“统一控制”：一次为目标用户设置六个模块。
2. 每个业务模块中的独立入口：只修改当前模块中目标用户的规则。

六个模块分为两类，界面文案与可选值不同：

| 模块类别 | 模块 | 控制名称 | 可选控制值 |
| --- | --- | --- | --- |
| 交易类 | 交割、永续、现货 | 用户点控 | 盈利、亏损 |
| 理财类 | AI量化、流动性挖矿、投资组合 | 用户点控 | 高收益、低收益 |

两类控制都支持“单次生效”和“长期生效”。

## 3. 用户管理页面

### 3.1 用户列表增强

在现有用户列表增加以下列：

| 列名 | 展示内容 |
| --- | --- |
| 用户控制 | 未设置、盈利、亏损、存在模块差异 |
| 生效方式 | 单次生效、长期生效，未设置时显示“—” |
| 模块状态 | `6/6 已同步`、`已执行 N/6`、`N/6 存在差异` |
| 更新时间 | 最近一次统一设置或模块独立设置时间 |
| 操作 | 设置控制、修改控制、取消控制、查看详情 |

“盈利”表示交易类盈利且理财类高收益；“亏损”表示交易类亏损且理财类低收益。列表中必须通过说明或悬浮提示解释该映射，避免误以为理财产品采用本金亏损语义。

### 3.2 统一控制弹窗

弹窗字段如下：

| 字段 | 规则 |
| --- | --- |
| 目标用户 | 只读展示 UID、用户名和邮箱 |
| 控盘类型 | 盈利、亏损 |
| 交易类效果 | 随控盘类型自动展示“盈利”或“亏损”，不可单独修改 |
| 理财类效果 | 随控盘类型自动展示“高收益”或“低收益”，不可单独修改 |
| 生效方式 | 单次生效、长期生效 |
| 覆盖范围 | 固定展示交割、永续、现货、AI量化、流动性挖矿、投资组合 |
| 点控备注 | 必填 |

统一控盘类型映射：

| 控盘类型 | 交割、永续、现货 | AI量化、流动性挖矿、投资组合 |
| --- | --- | --- |
| 盈利 | 盈利 | 高收益 |
| 亏损 | 亏损 | 低收益 |

弹窗底部明确提示：保存会覆盖该用户在六个模块中的现有规则；任一模块设置失败，六个模块全部保持原状态。

长期生效、覆盖已有规则和统一取消均需要二次确认。界面可复用项目现有 MFA 验证弹窗表现高风险操作流程。

### 3.3 用户控制详情

从用户列表打开详情抽屉或弹窗，展示六个模块的当前状态：

| 字段 | 内容 |
| --- | --- |
| 模块 | 六个模块名称 |
| 控制内容 | 盈利、亏损、高收益或低收益 |
| 生效方式 | 单次生效或长期生效 |
| 当前状态 | 待执行、生效中、已执行、已取消、已覆盖 |
| 来源 | 用户管理统一设置、模块独立设置 |
| 更新时间 | 最近更新时间 |
| 最近执行 | 最近一次模拟执行时间和业务单号 |

详情需要区分两种情况：

- 单次生效规则被正常逐模块执行：显示“已执行 N/6”，不标记为配置差异。
- 某模块被独立修改：显示“N/6 存在差异”，并突出差异模块。

### 3.4 用户管理取消

用户管理中的取消操作影响全部六个模块。确认弹窗列出当前仍有效的模块规则，确认后统一变为已取消。已执行的单次生效规则仅保留历史，不重复处理。

## 4. 模块独立页面

### 4.1 菜单入口

在每个模块的管理菜单下增加独立入口：

| 模块 | 菜单名称 |
| --- | --- |
| 交割 | 用户点控 |
| 永续 | 用户点控 |
| 现货 | 用户点控 |
| AI量化 | 用户点控 |
| 流动性挖矿 | 用户点控 |
| 投资组合 | 用户点控 |

### 4.2 通用列表

六个页面共用一套页面结构，按模块切换标题、可选控制值和说明文案。

列表字段：

- UID、用户名和邮箱；
- 当前控制内容；
- 单次生效或长期生效；
- 当前状态；
- 规则来源；
- 更新时间；
- 设置、修改、取消、查看日志操作。

支持按 UID、用户名、邮箱搜索，并支持按控制内容、状态和来源筛选。

### 4.3 模块设置弹窗

交易类模块字段：目标用户、盈利/亏损、单次生效/长期生效、点控备注。

理财类模块字段：目标用户、高收益/低收益、单次生效/长期生效、点控备注。

模块弹窗必须提示“本次操作只影响当前模块”。模块独立设置允许覆盖用户管理统一下发的当前模块规则，其他五个模块保持不变。设置完成后，用户列表显示模块差异。

### 4.4 模块取消

模块页面中的取消只影响当前模块。取消后，其他模块继续使用各自当前规则，用户管理列表更新为存在模块差异。

### 4.5 交易类执行说明

交割、永续和现货的模块页面需要明确说明：用户点控只作用于目标用户的最终结算，不改变全局行情、K线或实时浮动盈亏。

交易类模块的用户控制详情增加以下只读信息：

| 字段 | 内容 |
| --- | --- |
| 作用阶段 | 最终结算 |
| 行情影响 | 不修改全局行情和K线 |
| 实时浮盈亏 | 不修改 |
| 当前优先级 | 单笔/持仓控制、用户级控制、全局场控或自然结果 |
| 适用对象 | 下一笔有效订单/持仓，或长期生效作用于后续有效订单/持仓 |

永续页面需特别区分“合约级插线”和“用户级控盘”：合约级插线影响整份合约；用户级控盘不调用全局插线，只在目标用户平仓结算时决定最终盈亏方向。

## 5. 日志界面

Demo 提供统一日志视图，支持按 UID、模块、来源、动作和时间筛选。

### 5.1 操作日志

展示操作人、时间、入口、目标用户、影响模块、修改前规则、修改后规则、生效方式、备注和模拟批次号。

### 5.2 执行日志

展示模块、目标用户、规则内容、单次生效/长期生效、模拟业务单号、执行前结果、执行后结果、执行状态和时间。

交易类展示全局/自然结算方向和用户最终结算方向；理财类展示执行前后收益档位。Demo 不需要展示真实价格、金额或收益率。

## 6. Demo 状态与模拟操作

前端状态至少覆盖：

- 未设置；
- 单次生效待执行；
- 长期生效中；
- 单次生效已执行；
- 已取消；
- 已覆盖；
- 模块存在差异；
- 统一设置失败。

Demo 提供以下模拟能力：

1. 用户管理统一设置六个模块。
2. 任一模块独立覆盖当前模块。
3. 模拟某模块的单次生效规则执行完成。
4. 用户管理统一取消六个模块。
5. 模块页面只取消当前模块。
6. 模拟某模块设置失败，验证六个模块均保持旧状态。

## 7. 组件建议

为避免六个模块复制页面，界面实现建议拆为：

- `UserUnifiedControlModal`：用户管理统一控制弹窗；
- `UserControlDetailDrawer`：六模块状态详情；
- `ModuleUserControlPage`：模块独立控制通用页面；
- `ModuleUserControlModal`：模块设置弹窗；
- `UserControlLogView`：统一日志视图；
- `userControlState`：Demo 的共享模拟状态。

这只是前端组件边界建议，不定义后端接口。

## 8. 界面验收标准

1. 用户管理能够设置盈利或亏损控盘类型，并清楚展示两类模块的实际效果。
2. 统一设置成功后，详情中六个模块均显示新规则和“用户管理统一设置”来源。
3. 模块独立设置只修改当前模块，用户列表显示存在差异。
4. 用户管理再次设置时重新覆盖六个模块，状态恢复为 `6/6 已同步`。
5. 用户管理取消影响六个模块，模块取消只影响当前模块。
6. 单次生效规则可按模块独立模拟执行，并正确显示“已执行 N/6”。
7. 模拟任一模块设置失败时，不展示任何新规则，旧状态保持不变。
8. 理财模块界面只出现高收益/低收益，不出现盈利/亏损。
9. 所有设置、覆盖、取消和模拟执行均能在日志视图中找到对应记录。
10. 永续用户级控盘界面明确标注“不改变K线与实时浮盈亏，仅作用于最终平仓结算”。
11. Demo 能展示单笔/持仓控制、用户级控制、全局场控和自然结果四级优先关系。

## 9. 非目标

本次不实现真实 API、数据库、行情控制、订单结算、收益计算、权限后台或真实 MFA；这些内容由后续开发根据业务规则文档另行设计。
