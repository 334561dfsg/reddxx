# 用户点控状态流转与 Demo 数据设计

## 目标

用尽量少的状态表达用户点控从设置到结束的完整过程，并确保前端 Demo 中每种状态都有可查看的数据样例。规则说明另行形成开发文档，界面不增加服务器接口。

## 简化状态模型

### 当前规则状态

当前规则列表只表达管理员此刻能否继续操作：

| 状态 | 含义 | 可执行操作 |
| --- | --- | --- |
| 未设置 | 当前模块没有有效点控规则 | 设置 |
| 待执行 | 一次性规则已设置，等待下一次有效结算 | 修改、取消 |
| 生效中 | 永久规则已设置，持续影响后续有效结算 | 修改、取消 |

不在 Demo 中使用“处理中”。当前前端没有真实异步写入或结算过程，展示该中间状态会增加解释成本。

### 历史结果状态

结束状态只在用户详情、规则历史或用户点控日志中展示：

| 状态 | 含义 | 展示位置 |
| --- | --- | --- |
| 已执行 | 一次性规则已在一次有效结算中使用 | 模块列表、用户详情、执行日志 |
| 已取消 | 管理员主动取消当前规则 | 模块列表、用户详情、操作日志 |
| 已覆盖 | 修改或重新统一设置后，旧规则进入历史 | 用户详情的已覆盖规则历史、操作日志变更前快照 |
| 失败 | 设置或最终执行失败，当前有效规则不发生错误变更 | 用户点控日志 |

底层数据继续使用 `active` 区分当前规则，并通过 `duration` 映射界面文案：`once + active` 显示“待执行”，`permanent + active` 显示“生效中”。终态使用 `consumed`、`cancelled`、`superseded`。不再生成新的 `processing` Demo 数据。

## 状态流转

### 一次性规则

```text
未设置 → 待执行 → 已执行
            └→ 已取消
            └→ 已覆盖 → 新规则进入待执行或生效中
```

- 只有实际收益入账或最终结算成功才会进入“已执行”。
- 预估收益、浮动盈亏和行情变化不消费一次性规则。

### 永久规则

```text
未设置 → 生效中 → 已取消
            └→ 已覆盖 → 新规则进入待执行或生效中
```

- 单次成功执行不会结束永久规则。
- 永久规则只通过取消或新规则覆盖结束。

### 六模块统一设置

```text
六模块原状态 → 全部设置成功 → 六模块进入同一批新规则
六模块原状态 → 任一模块设置失败 → 六模块全部保持原状态 + 失败日志
```

模块独立设置只覆盖当前模块的规则，其他五个模块保持不变；被替换的旧规则进入“已覆盖”历史。

## Demo 数据矩阵

Demo 种子数据应保证以下场景可直接查看：

| 场景 | Demo 表现 |
| --- | --- |
| 未设置 | 至少一个列表用户在目标模块没有规则 |
| 一次性待执行 | 至少一个用户拥有 `once + active` 规则 |
| 永久生效中 | 至少一个用户拥有 `permanent + active` 规则 |
| 一次性已执行 | 至少一个用户的模块规则为 `consumed`，并有成功执行日志 |
| 已取消 | 至少一个用户的模块规则为 `cancelled`，并有取消操作日志 |
| 已覆盖 | 至少一个用户存在 `superseded` 规则历史和新生效规则 |
| 设置失败回滚 | 日志中存在失败记录；对应用户的六模块规则仍保持失败前状态 |
| 执行失败 | 日志中存在失败执行记录；一次性规则仍保持待执行 |
| 六模块统一 | 用户详情显示六模块来自同一统一批次 |
| 模块差异 | 统一设置后单独覆盖一个模块，详情标记配置差异 |
| 部分执行 | 统一一次性规则中一个模块已执行，其余模块仍待执行 |

## 界面展示原则

- 用户列表继续只显示“是否点控中”，不增加多列状态。
- 模块用户点控列表显示当前模块状态，允许通过状态筛选查看未设置、待执行、生效中、已执行和已取消。
- 用户详情区分当前规则、已覆盖历史和最近执行，不把历史终态伪装成当前有效规则。
- 用户点控日志统一展示设置、取消和执行记录，并用“成功／失败”表达操作结果。
- 失败不改变当前规则状态；失败原因只出现在日志中。

## 实现边界

- 调整前端 Mock 种子和必要的状态映射，使数据矩阵中的场景可见。
- 必要时补充失败日志字段，但不模拟服务器请求和真实异步过程。
- 保留现有用户管理统一设置、模块独立设置、一次性和永久规则逻辑。
- 不新增“处理中”操作入口或模拟工具。

## 验证标准

- 自动化测试逐项验证 Demo 数据矩阵。
- 模块列表、用户详情和用户点控日志能展示对应状态。
- 全量测试及生产构建通过。
- 浏览器抽查至少覆盖待执行、生效中、已执行、已取消、已覆盖和失败日志。
