# 用户列表统一操作下拉菜单设计

## 目标

将用户列表的常规用户操作与点控操作集中到同一个下拉菜单，同时根据用户状态和点控状态动态显示可用入口。

## 菜单结构

常规用户操作区依次展示：

- 用户详情
- 封户或解封：根据当前用户状态显示对应名称
- 调账
- 入金
- 划转

分隔线下方为点控操作区：

- 未点控用户只显示“点控”
- 点控中的用户只显示“取消点控”
- “点控日志”始终显示

## 交互

- “用户详情”打开现有用户详情抽屉。
- “封户/解封、调账、入金、划转”直接打开现有对应操作弹窗，不要求先进入用户详情。
- “点控”打开现有统一点控弹窗。
- “取消点控”打开现有取消点控确认流程。
- “点控日志”跳转到当前用户的用户点控日志页面。
- 选择任一菜单项后关闭下拉菜单。

## 组件衔接

复用现有 `UserFreezeAction`、`UserAdjustAction`、`UserDepositAction` 和 `UserTransferAction`，为这些组件暴露打开弹窗的方法。用户列表为当前操作用户挂载一组无按钮触发器，并通过组件引用打开对应弹窗，不复制表单或业务逻辑。

## 范围

本次只调整前端原型交互和对应测试，不改变用户操作、点控规则、Mock 数据或路由的数据结构。

## 验收

- 用户列表只有一个“操作”下拉菜单。
- 菜单包含全部常规用户操作。
- “点控”和“取消点控”按状态互斥出现。
- 四类常规操作可从列表菜单直接打开原有弹窗。
