# 编辑会员等级选择器设计

## 目标

让“编辑会员等级”在等级数量较多、等级名称或副标题缺失时仍保持紧凑、易搜索、可访问，并保持现有 MFA 提交业务不变。

## 交互方案

- 将平铺的会员等级单选卡片替换为项目共享的 `PanelSingleSelect` 可搜索单选组件。
- 选择器按等级编号、主名称和可选副标题搜索；列表顺序沿用后端返回的启用等级顺序。
- 当前等级保留在候选列表中但禁用，并明确标记“当前等级”；不能提交当前等级。
- 打开选择器后的搜索、键盘导航和候选高亮不改变已提交值，只有点击或键盘确认启用选项时才更新目标等级。
- 弹窗打开时将初始焦点放到等级选择器；返回编辑阶段时恢复到该选择器。

## 文案与缺省规则

- 主标题优先使用非空 `displayName`，其次使用非空 `name`，最后回退为 `VIP{level}`。
- 副标题使用与主标题不同的非空 `name`；不存在或与主标题相同时不渲染副标题，不预留高度。
- 权益不再作为选择列表的默认副标题，也不再用“标准会员权益”填补缺失内容。
- 确认页沿用同一标题与副标题规则；副标题缺失时仅显示主标题。权益字段仅在确有权益数据时显示。

## 数据与提交

- `form.vipLevel` 继续保存等级数值，MFA payload 保持 `{ userId, vipLevel, reason }`。
- 选择器 options 在组件内由 `enabledVipLevels` 派生，包含稳定 value、label、可选 description、disabled 与搜索关键词。
- 数据刷新后若已选等级不存在或被禁用，选择器保留失效值并阻止进入确认阶段，要求重新选择。

## 布局与可访问性

- 选择器维持单行触发器，候选数量不再增加 Dialog 初始高度；候选面板自行限制高度和滚动。
- 继续使用现有 Dialog 固定头尾、单一内容滚动区、关闭保护和共享层级。
- 复用 `PanelSingleSelect` 的键盘、ARIA、焦点返回、弹层定位及窄视口行为，不新增第二套选择器实现。

## 验证

- 覆盖大量等级的搜索与选择、无副标题等级的紧凑渲染、当前等级禁用、失效选择阻止提交，以及 MFA payload 不变。
- 回归 Dialog 的遮罩不关闭、焦点约束、固定头尾、关闭动画、Reduced Motion 和异步忙碌保护。
- 运行全量测试与生产构建；未实际覆盖的真实浏览器视口和输入方式必须在交付说明中列出。
