## 1. 操作

- 在“现货管理／用户点控”中，管理员可为单个用户设置控盘类型和控盘方式；规则默认长期生效，不填写具体金额、价格或收益率。
- 控盘方式支持：盈利、亏损；从用户管理选择做高/做低方式时，现货按默认盈利或默认亏损处理。
- 同一用户在现货模块同一时刻只有一条当前用户点控规则；模块点控与用户点控设置仅表示来源，最后一次成功设置替换当前规则，被覆盖规则不恢复。
- 模块点控、修改或取消只影响现货模块；用户管理点控设置以同一批次更新交割、永续、现货三个交易模块。修改产生新规则并将旧规则置为“已覆盖”，取消只取消当前规则。

## 2. 触发

- 当前仅在卖出成交完成、原始已实现净盈亏计算完成，并准备进行最终结算入账时，按当前有效规则判断。
- 持仓市值变化、未卖出资产的浮动盈亏和未形成原始已实现净盈亏的成交不触发。原始结算或损益调整入账失败属于执行失败；如为历史一次性规则，也不消耗执行机会。
- 用户点控不修改公共行情、K 线、盘口、真实成交价格、原始成交记录或其他用户结果。

## 3. 规则

- 现货采用“双结果模型”：`原始交易净盈亏 + 点控调整金额 = 用户最终结算净盈亏`。点控调整金额由系统按现货模块规则自动计算，不是运营配置项；原始交易净盈亏仍按真实卖出成交、对应成本和手续费计算并独立保存。
- 自然结果已符合控盘类型时，损益调整金额为 `0`，直接使用自然结果；自然结果不符合时，由现货模块按配置的最小盈利或最小亏损阈值计算调整金额。目标盈利要求最终净盈亏 `> 0`，目标亏损要求最终净盈亏 `< 0`。
- 做高盈利、做低盈利、做高亏损、做低亏损只表示最终盈亏幅度，具体调整金额由现货模块按自身高/低幅度规则计算，并作为独立账务调整记录。
- 点控调整必须作为独立账务记录入账：正数表示平台补贴，负数表示平台扣减。不得反向修改真实成交价格、成交数量、成本、手续费或原始交易净盈亏。
- 原始净盈亏为 `0` 时可继续执行点控调整；只有最终结算净盈亏达到目标方向且调整入账成功，才算执行成功。缺少卖出成交、成本、手续费、调整资金科目或其他必要依据时执行失败。
- 新增或修改的点控规则长期生效，对后续每次符合条件的卖出结算分别判断和调整，直到被取消或被新规则覆盖。
- 历史一次性规则只有本次实际选中并成功用于最终结算时才消耗执行机会；被更高优先级规则挡住则不消耗。
- 结果优先级固定为：单笔订单或持仓控制 > 当前有效用户点控 > 模块全局场控 > 自然结果。

## 4. 状态

- 新增或修改的长期规则设置后为“生效中”；一次成功入账后仍为“生效中”。
- 历史一次性规则设置后为“待执行”；最终结算方向满足规则且原始结果与损益调整全部入账成功后为“已执行”；调整入账失败、计算依据缺失或被更高优先级规则挡住时仍为“待执行”。
- 新设置替换时旧规则为“已覆盖”，取消时当前规则为“已取消”；两种情况均不恢复更早规则。
- 一次设置、修改或取消各记一条操作日志，记录来源、影响范围、变更前后、操作人、时间、备注和批次号；覆盖是该条日志中的变更结果，不另记操作日志。
- 每个业务结果执行记一条执行日志，记录业务单号、原始交易净盈亏、损益调整金额、最终结算净盈亏、规则方向及成功或失败；原始成交记录和调整账务记录可分别追溯。

## 5. 验收点

- 管理员只能设置控盘类型和控盘方式，不能填写控制周期、金额、价格或收益率；新规则默认长期生效。
- 模块点控现货规则后，其他模块的规则和状态不变。
- 用户点控设置会替换现货当前规则；之后成功的现货点控可再替换它，取消后均不恢复已覆盖规则。
- 当前仅卖出成交完成、原始净盈亏计算完成并进入最终结算时才可触发现货规则；持仓市值和未卖出资产的浮动盈亏不触发。
- 卖出后先按真实成交、成本和手续费计算原始交易净盈亏，再通过独立损益调整形成最终结算净盈亏；原始成交记录不被修改。
- 自然结果符合目标方向时调整金额为 `0`；不符合时，盈利控制通过平台补贴使最终结果 `> 0`，亏损控制通过平台扣减使最终结果 `< 0`。
- 新规则保存后默认“生效中”，后续符合条件的现货卖出结算持续判断，直到取消或覆盖。
- 原始净盈亏为 `0` 时仍可执行调整；缺少计算依据、调整资金科目或调整入账失败时执行失败并有失败日志。
- 点控不修改公共行情、K 线、盘口、真实成交价格、原始盈亏或其他用户结果。
- 一次设置、修改或取消各有一条字段完整的操作日志；执行日志能够同时核对原始净盈亏、调整金额、最终净盈亏和成败。
