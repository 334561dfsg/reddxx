## 1. 操作

- 在“交割管理／用户点控”中，管理员可为单个用户设置盈利或亏损，以及一次性或永久生效方式；不填写具体金额、价格或收益率。
- 同一用户在交割模块同一时刻只有一条当前用户点控规则；模块独立设置与用户管理统一设置仅表示来源，最后一次成功设置替换当前规则，被覆盖规则不恢复。
- 模块独立设置、修改或取消只影响交割模块；统一设置以同一批次更新六个模块。修改产生新规则并将旧规则置为“已覆盖”，取消只取消当前规则。

## 2. 触发

- 仅在交割合约到期并完成最终结算时，按当前有效规则判断。
- 行情变化、合约持有期间展示、未到期订单、未完成或失败的结算均不触发，也不消耗一次性规则。
- 用户点控不修改公共行情或其他用户的结算结果。

## 3. 规则

- 点控只约束目标用户最终为盈利或亏损，具体金额由订单本金、周期、产品赔率和费用按交割产品规则计算，并以扣除费用后的已实现净结果判断。
- 已实现净结果 `> 0` 为盈利、`< 0` 为亏损、`= 0` 既非盈利也非亏损；零值执行失败，一次性规则仍为“待执行”。缺少订单本金、周期、赔率、费用等必要计算依据时同样执行失败且不消耗一次性规则。
- 只有本次实际选中并成功用于最终结算结果的规则才消耗一次性机会；自然结果原本符合目标方向但该规则被选中参与成功结算，仍为成功执行并消耗；被更高优先级规则挡住则不消耗。
- 永久规则对后续每次符合条件的最终结算持续生效，直到被取消或被新规则覆盖。
- 结果优先级固定为：单笔订单或持仓控制 > 当前有效用户点控 > 模块全局场控 > 自然结果。

## 4. 状态

- 一次性规则设置后为“待执行”；被选中并成功用于最终结算后为“已执行”；结算失败、零值、计算依据缺失或被更高优先级规则挡住时仍为“待执行”。
- 永久规则设置后为“生效中”；单次成功结算后仍为“生效中”。
- 新设置替换时旧规则为“已覆盖”，取消时当前规则为“已取消”；两种情况均不恢复更早规则。
- 一次设置、修改或取消各记一条操作日志，记录来源、影响范围、变更前后、操作人、时间、备注和批次号；覆盖是该条日志中的变更结果，不另记操作日志。
- 每个业务结果执行记一条执行日志，记录业务单号、执行前后结果及成功或失败。

## 5. 验收点

- 管理员只能设置盈利／亏损和一次性／永久，不能填写金额、价格或收益率。
- 模块独立设置交割规则后，其他五个模块的规则和状态不变。
- 统一设置会替换交割当前规则；之后成功的交割独立设置可再替换它，取消后均不恢复已覆盖规则。
- 只有合约到期且最终结算成功时，交割一次性规则才可能变为“已执行”。
- 扣费后已实现净结果 `> 0` 判为盈利、`< 0` 判为亏损；`= 0` 执行失败且一次性规则仍为“待执行”。
- 缺少订单本金、周期、赔率或费用等必要计算依据时执行失败，一次性规则不消耗并有失败执行日志。
- 当前用户点控被选中并成功结算时，即使自然结果已符合目标方向也消耗一次性机会；被单笔订单或持仓控制挡住时不消耗。
- 最终金额按交割产品规则计算，用户点控不修改公共行情或其他用户结果。
- 一次设置、修改或取消各有一条字段完整的操作日志，每个业务结果执行有一条包含业务单号、前后结果和成败的执行日志。
